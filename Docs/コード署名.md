# コード署名

このリポジトリの Desktop アプリと ProjectCli の Release publish 出力にある EXE/DLL を署名する手順です。

## 開発用の自己署名証明書

次のコマンドを PowerShell で実行します。証明書は現在のユーザーの証明書ストアにだけ作成・信頼登録され、秘密鍵はリポジトリに保存されません。

```powershell
$certificate = .\scripts\ForSmartAppControl\New-DevelopmentCodeSigningCertificate.ps1
$certificate.Thumbprint
```

出力された拇印を指定して、Release publish と署名を実行します。

```powershell
.\scripts\ForSmartAppControl\Publish-AndSign.ps1 -CertificateThumbprint '<拇印>'
```

成果物は `artifacts/signed` に作成されます。特定の Windows ランタイム向けに publish する場合は `-RuntimeIdentifier win-x64` を追加します。

Desktop アプリは MonoGame が `SDL2.dll` などのネイティブ DLL を動的に読み込むため、単一 EXE にはまとめません。配布フォルダー内の EXE と DLL は、ネイティブ DLL を含めて一つずつ署名・検証されます。JSON、画像など実行コードではないファイルには Authenticode 署名を付けません。配布時は EXE だけを取り出さず、生成されたフォルダー全体を ZIP にしてください。

自己署名証明書は作成した Windows ユーザーでのみ信頼されます。他の PC に配布する用途や Smart App Control の信頼を得る用途には使用しません。

## 公開リリース用の CA/EV 証明書

認証局から取得したコードサイニング証明書を、署名を行う Windows ユーザーの `CurrentUser\My` 証明書ストアへインポートします。その証明書の拇印とタイムスタンプサーバーを指定します。

```powershell
.\scripts\ForSmartAppControl\Publish-AndSign.ps1 `
  -CertificateThumbprint '<CA または EV 証明書の拇印>' `
  -RuntimeIdentifier win-x64 `
  -TimestampServer 'http://timestamp.digicert.com'
```

PFX のパスワードや秘密鍵をリポジトリ、ソースコード、ログに保存しないでください。EV 証明書の USB トークンまたはクラウド署名を使う場合は、認証局の署名ツールで publish 出力の EXE/DLL を署名してください。

## 署名のみを行う場合

既存の publish 出力は次のように再帰的に署名・検証できます。

```powershell
.\scripts\ForSmartAppControl\Sign-ReleaseArtifacts.ps1 `
  -Path '.\artifacts\signed\CircleSpaceCoordinator.Desktop' `
  -CertificateThumbprint '<拇印>' `
  -TimestampServer 'http://timestamp.digicert.com'
```

## Visual Studio の F5 実行

`CircleSpaceCoordinator.Desktop` の Debug ビルドでは、ビルド完了後に
`scripts/ForSmartAppControl/Sign-BuildOutput.ps1` が自動実行されます。
現在の Windows ユーザーの証明書ストアから有効な開発用証明書を選び、
`bin/Debug` の EXE/DLL を署名してからアプリを起動します。

一時的に自動署名を無効化する場合は、MSBuild プロパティ
`SmartAppControlSigningEnabled=false` を指定してください。

## 将来の選択肢：SignPath Foundation

調査日：2026-09-04

[SignPath Foundation](https://signpath.org/) は、条件を満たすオープンソースプロジェクトに対して、コード署名証明書と SignPath.io の署名サービスを無料で提供しています。証明書の秘密鍵は開発者へ配布されず、SignPath 側の HSM で生成・保管されます。証明書の名義はプロジェクトや開発者個人ではなく、原則として `SignPath Foundation` です。

Circle Space Coordinator の Windows 向け EXE/DLL の Authenticode 署名にも利用できる可能性があります。ただし、署名を付ければ Windows SmartScreen の警告が直ちに、または必ず表示されなくなるとは限りません。

### 現在は申請しない

現在、この GitHub リポジトリは業務情報を含むため private で運用しています。業務情報を完全に撤去し、ソースコード、履歴、リリース成果物、ドキュメントのすべてを安全に公開できる状態になるまでは、SignPath Foundation の利用申請および公開リポジトリとの連携を行いません。

公開準備では、現在のファイルだけでなく Git の過去のコミット、削除済みファイル、タグ、成果物、ログなどに業務情報や個人情報、認証情報が残っていないことも確認する必要があります。機密情報が過去の履歴に含まれていた場合は、単に最新コミットから削除するだけでは不十分です。

### 主な利用条件

詳細と最新情報は [SignPath Foundation conditions for Open Source projects](https://signpath.org/terms.html) を確認してください。2026-09-04 時点で確認した主な条件は次のとおりです。

- OSI 承認済みのオープンソースライセンスを、署名対象の全構成要素に使用していること
- 商用デュアルライセンスや、プロジェクト関係者による非公開・プロプライエタリなコードを含まないこと
- マルウェア、不要なプログラム、攻撃・保護回避を目的とする機能を含まないこと
- プロジェクトが活発に保守されていること
- 署名したいものと同じ形式の成果物がすでにリリースされ、機能が公開ページに説明されていること
- 署名する成果物が、自分たちのリポジトリのソースコードとビルドスクリプトから検証可能な方法で構築されること
- リポジトリと SignPath のアカウントで多要素認証を使用すること
- Author、Reviewer、Approver の責任範囲と担当者を定めること
- 各リリースの署名要求を手動承認すること
- Code signing policy、プライバシーポリシー、アンインストール方法を公開すること
- 製品名とバージョンなど、署名対象ファイルのメタデータを一貫して設定すること

Foundation 名義の証明書を利用するため、条件を満たしていても採否は SignPath Foundation の判断になります。規約違反時にはサービス停止や証明書失効の可能性があります。

### 公開・申請前のチェックリスト

- [ ] 業務情報、個人情報、秘密情報、認証情報を現行ファイルから撤去する
- [ ] Git の全履歴、タグ、過去の成果物にも機密情報が残っていないことを確認する
- [ ] 公開してよい第三者素材と依存関係だけで構成されていることを確認する
- [ ] `LICENSE.txt` の `[year]` と `[fullname]` を正式な表記に置き換える
- [ ] リポジトリを安全に public 化する
- [ ] Windows 向けの未署名成果物を GitHub Releases などで一度公開する
- [ ] README またはダウンロードページに機能と配布物を説明する
- [ ] Code signing policy、チームの署名担当、プライバシーポリシーを公開する
- [ ] インストールする場合はアンインストール手順も公開する
- [ ] GitHub の多要素認証を有効にする
- [ ] GitHub-hosted runner を使う再現可能な Release ビルドを GitHub Actions に構築する
- [ ] EXE/DLL の製品名、バージョン、著作権などのメタデータを整備する
- [ ] [申請ページ](https://signpath.org/apply)から申請する

承認後は SignPath GitHub App と公式の署名 Action を CI に組み込みます。OSS 向け署名では、署名対象が GitHub Actions の成果物として保存されていることや、署名までのジョブが GitHub-hosted runner 上で実行されたことなどが検証されます。実装時は [SignPath の GitHub 連携資料](https://docs.signpath.io/trusted-build-systems/github) と [コード署名資料](https://docs.signpath.io/signing-code) の最新版に従います。
