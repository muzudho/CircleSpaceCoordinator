# 机配置とサークル配置の分離

## 目的

配置案を、物理会場を決める **DeskLayout（机配置）** と、その机へサークルを割り当てる **CircleLayout（サークル配置）** に分離する。
一般参加者評価で採用した机配置を共通にしつつ、複数のジャンル配置・サークル配置を比較できるようにする。

## データモデル

```text
CircleSpaceProject
|- DeskLayouts[]
|  |- DeskPlacements
|  |- SeatLabels
|  |- IslandConnectors
|  |- DisabledIslandConnections
|  `- FacingRegions
`- CircleLayouts[]
   |- DeskLayoutId  (DeskLayout を必ず一つ参照する)
   `- Assignments
```

`DeskLayout` は机、席名、島定義、向かい定義を所有する。`CircleLayout` はサークル割当てだけを所有する。
評価は `CircleLayout` ごとに行う。一般参加者評価もサークルのジャンル並びに依存するため、同じ `DeskLayout` 配下でも値は異なり得る。

## UI の原則

- ［机配置］と［島定義］では `DeskLayout` の一覧を表示・編集する。
- ［ジャンル配置］と［サークル配置］では、選択中の `DeskLayout` に属する `CircleLayout` の一覧を表示・編集する。
- `CircleLayout` の作成時は対象 `DeskLayout` を指定する。通常は現在選択中の机配置を既定にする。
- 机配置を編集すると、それを参照するすべてのサークル配置へ即時に反映される。割当てが机の変更後に不正になる編集は拒否する。

### Desktop 操作

右側の一覧上部に `+`、`-`、`Link` を表示する。［机配置］・［島定義］では `+` と `-` が DeskLayout の追加・削除、［ジャンル配置］・［サークル配置］では `+` と `-` が CircleLayout の追加・削除、`Link` が選択中 CircleLayout の DeskLayout 紐付け変更である。削除と紐付け変更は確認または選択ダイアログを経由する。

## 削除規則

1. `CircleLayout` は確認ダイアログを表示して削除できる。
2. 参照中の `CircleLayout` が一つでもある `DeskLayout` は削除できない。
3. 参照中の `CircleLayout` がない `DeskLayout` は、確認ダイアログを表示して削除できる。
4. 削除不能の通知には、参照しているサークル配置案の件数を表示し、先に削除または別の机配置へ移すよう案内する。

## 永続化と移行

- JSON は `deskLayouts` と `circleLayouts` を保存する新形式にする。
- 既存の `plans` を読む場合は、各 Plan から同名・同 ID の `DeskLayout` と、それを参照する `CircleLayout` を一組ずつ作る。これにより旧プロジェクトを失わず開ける。
- 新形式で保存した後は `plans` を書き出さない。
- 旧 `schemaVersion` を読む互換性は維持し、新形式はスキーマを更新して検証する。

## 実装の進め方・再開手順

1. Core: `DeskLayout`／`CircleLayout` を導入し、評価・検証を参照関係へ対応させる。
2. Application: 作成・複製・削除・机配置編集・サークル割当てを各レイアウト ID へ分ける。
3. Infrastructure: JSON と schema の読み書き、および旧 `plans` からの読み込み移行を実装する。
4. Desktop: モードごとに対応する一覧を表示し、削除確認と参照中削除拒否を実装する。
5. Tests: 参照整合性、削除規則、評価、旧 JSON 移行を追加し、`dotnet build CircleSpaceCoordinator.slnx` と各テスト実行で確認する。

作業を中断した場合は、まずこの文書、`git status --short`、次に Core のモデル・検証・JSON 形式を確認してから再開する。既存プロジェクトの読み込み互換性を壊さないことを最優先にする。
