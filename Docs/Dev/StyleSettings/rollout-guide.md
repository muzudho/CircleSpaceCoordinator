# 新しいページへの導入手順

[実装指針](README.md) に沿って、新しいページへスタイル設定を接続するための手順です。

## 1. 移行範囲を決める

対象ページの描画、クリック判定、座標変換、リサイズ時の再生成、入力モデルの寿命を確認します。最初の変更では外側の領域だけを移して構いません。

実装前に、次の表を対象ページの役割で埋めてください。

| C# の役割 | モデルの完全パス | 型 | 配置を適用する先 |
| --- | --- | --- | --- |
| 見出し | `/example/title` | `container` | 文字描画の矩形 |
| 本文 | `/example/body` | `container` | 既存の本文配置処理 |
| 確定操作 | `/example/apply` | `button` | 描画・入力が共有するボタン |

この表は例です。イベント一覧のモデル数・階層・Id を別のページの必須条件にしないでください。

## 2. 原本と埋め込みを追加する

1. `App_Doc/<page>.style-settings.md` に JSON の原本を置く。
2. `models` / `layouts` / `bindings` を作り、現在の配置を再現する。
3. 読み込みを担当するプロジェクトの `.csproj` に `EmbeddedResource` を追加する。
4. Debug だけ、原本の絶対パスを AssemblyMetadata へ記録する。
5. アプリ用の生成処理では Debug が原本、Release が埋め込みを選ぶようにする。

`.csproj` の形は次のとおりです。名前は対象ページに置き換えます。

```xml
<ItemGroup>
  <EmbeddedResource Include="../App_Doc/example.style-settings.md"
                    Link="App_Doc/example.style-settings.md"
                    LogicalName="CircleSpaceCoordinator.ExampleStyle.json" />
  <AssemblyMetadata Include="ExampleStyleSource"
                    Value="$([System.IO.Path]::GetFullPath('$(MSBuildProjectDirectory)/../App_Doc/example.style-settings.md'))"
                    Condition="'$(Configuration)' == 'Debug'" />
</ItemGroup>
```

原本を出力フォルダーへコピーする設定は不要です。Debug の実行ファイルを別の PC へ配っても、記録した原本パスが使えるとは限りません。配布物は Release で作成します。

## 3. 読み込みと検証を接続する

埋め込みの原本を解析・検証して初期値にします。Debug では原本を一度読み込み、その後は `styleAutoReload` に従って監視します。既存のイベント一覧と同じ設定を使うなら、ページごとに別の有効／無効キーを増やさないでください。

読み込み・解析・画面固有の検証がすべて成功した場合だけ Current と Revision を更新します。エラーはログだけでなく、開発中の画面から原因を確認できる場所にも表示します。元ファイルは読み取り専用として扱います。

## 4. 入力前に配置を適用する

監視と配置適用は入力判定より前に行います。描画時にしか再配置しない実装では、クリック判定が1フレーム前の位置を使う可能性があります。

キャッシュの条件に、設定の Revision と、配置を変える幅・高さ・倍率・表示モードなどを含めます。反復する一覧では、行ひな型を一度配置して再利用し、各行・各文字の描画ごとにページ全体を再計算しないようにします。

部品数や構造が変わらない寸法変更であれば、入力モデルを保持して矩形だけを更新することを優先します。配置済みの矩形を背景・文字・入力で共用しているか、コード上で確認します。

## 5. 検証する

| 確認対象 | 期待する結果 |
| --- | --- |
| 正常な設定変更 | 再ビルドなしで描画と入力の両方が移動する |
| 同じ幅・高さでの変更 | Revision によって配置キャッシュが更新される |
| 無効中の変更と再有効化 | 無効中は維持し、再有効化後に最新の内容を採用する |
| 起動時に監視無効 | Debug では原本を一度読み込む |
| 不正 JSON、欠落パス、型違い、必須 binding 欠落 | 直前の正常な配置を維持し、エラーを表示する |
| 初回の原本欠落・破損 | 埋め込みへフォールバックし、原本は作成・上書きしない |
| 誤りを修正して保存 | 正常な配置へ復旧し、エラーが消える |
| リサイズ、小さい画面、0サイズ | 寸法が非有限値にならず、表示可能な行数やクリップが妥当 |
| 編集中・選択中・押下中のリロード | 文字・選択・フォーカスを維持し、移動したボタンを誤発火させない |
| 設定保存の成功・失敗 | 成功時だけ切り替えを確定し、再起動でも復元できる |
| 起動時のカレントディレクトリー変更 | 原本パスの解決が変わらない |
| Release | アプリ用の生成処理が埋め込みを選び、監視を実行しない |
| 新規の publish 出力 | 外部スタイルが不要で、原本の内容がアセンブリーへ埋め込まれる |

コアのテストでは一時ディレクトリーのファイルと `Update` に渡す経過時間を使い、実際の待機時間や実ユーザーの設定に依存しないようにします。描画とクリックの一致は実画面でも確認します。

イベント一覧のテストには導入時の既定寸法の数値を確認する箇所があります。意図したスタイル調整で既定値が変わる場合は、その期待値もレビューしてください。横展開では「領域からはみ出さない」「選択を維持する」「設定の変更が結果へ届く」などの振る舞いを中心に検証すると、寸法を調整しやすくなります。

Debug と Release の両方で確認します。新しいページに応じたテストを追加した上で、既存の実行例は次のとおりです。

```powershell
dotnet run --project tests/CircleSpaceCoordinator.Desktop.Tests -c Debug -p:SmartAppControlSigningEnabled=false
dotnet run --project tests/CircleSpaceCoordinator.Desktop.Tests -c Release -p:SmartAppControlSigningEnabled=false
```

埋め込みは「ファイルをリソースとして含める」だけなので、不正な JSON でも通常のコンパイルは通り得ます。CI では対象ページの全原本を解析・契約検証するテストを実行することを勧めます。また、以前の出力フォルダーにコピーされたファイルが残っていると配布確認を誤るため、新規の publish 出力先で確認してください。

## 6. 利用者へ引き継ぐ

編集する原本、調整可能な layout Id、固定しているモデル契約、C# に残した制約を書きます。「JSON に書ける」ことと「実画面へ接続済み」であることを区別してください。

Release は設定を埋め込むため、配布後の外部ファイル編集では変更できません。開発中のオートリロードと、リリースへの反映には再ビルドが必要なことを併記します。
