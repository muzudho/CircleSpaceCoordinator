## 記録4

［ー＿ー］  
Smart App Control は、未署名・評価（reputation）が不足した実行ファイルや、  
それが読み込む .dll をブロックすることがあります。配布・運用するなら、コード署名が正攻法です。  

1.	DLL と EXE の両方に Authenticode 署名を付与する
•	信頼された認証局（CA）からコードサイニング証明書を取得します。
•	現在は EV コードサイニング証明書が、Windows 側の信頼性・評価の面で特に有利です。
•	タイムスタンプを必ず付けます。

```plaintext
signtool sign /fd SHA256 /tr "http://timestamp.digicert.com" /td SHA256 /a ".\MyApp.exe"
signtool sign /fd SHA256 /tr "http://timestamp.digicert.com" /td SHA256 /a ".\MyLibrary.dll"
```

2.	署名を検証する

```plaintext
signtool verify /pa /v ".\MyApp.exe"
signtool verify /pa /v ".\MyLibrary.dll"
```

3.	開発中だけの対処: ダウンロード由来のブロックを解除する GitHub から ZIP を落とした場合などは、  
Mark of the Web が原因の場合があります。  

```plaintext
Unblock-File -Path ".\MyLibrary.dll"
```

フォルダー配下をまとめて解除する場合:  

```powershell
Get-ChildItem ".\publish" -Recurse | Unblock-File
```

ただし、これはダウンロードブロックの解除であり、  
Smart App Control の署名・評価判定そのものを恒久的に回避する方法ではありません。

4.	開発環境では Smart App Control を無効化できるが、推奨しない

Windows セキュリティの アプリとブラウザー コントロール > Smart App Control から変更できます。  
ただし、再度有効にするには通常 Windows のリセット／再インストールが必要になるため、  
開発専用の隔離環境以外では避けるのが安全です。

結論として、他者の PC でもブロックされない形で配布したいなら、  
リリース成果物の .exe と依存 .dll をすべて署名し、署名済みインストーラーまたは MSIX で配布してください。
