# 開発日誌から移動した記録

2026年9月の日誌から SAC に関係する記述を移動しました。以下は当時の記録です。最新の再発と運用方針は [現在のまとめ](README.md) を参照してください。

## 9月12日：SAC の再発と復旧報告

自作の `EditorClient.dll` が Smart App Control に拒否される事象が再発し、こちらの Debug 再ビルドでは解消しませんでした。その後、ユーザーがソリューション全体をクリーン→ビルド→起動したところ、ブロックされず起動できたとの報告がありました。成功手順と調査時点の失敗を区別して [調査記録](Smart%20App%20Control%E3%81%AB%E3%82%88%E3%82%8B%E8%B5%B7%E5%8B%95%E3%83%96%E3%83%AD%E3%83%83%E3%82%AF.md) に追記しました。内部の判定理由は確定しておらず、外部 DLL に自己署名を付けない方針を継続します。


## 9月12日の日誌：9月11日に外部 DLL への自己署名を廃止

9月11日の起動調査では、自己署名された `MonoGame.Framework.dll` が Windows のアプリ制御に拒否されていました。署名対象をこのリポジトリで作る EXE/DLL の許可リストに限定し、外部 DLL を元のパッケージの状態へ戻して再ビルドした後、開発者から起動成功の報告がありました。

今後も、他人が作った DLL・EXE には自己署名を追加せず、提供元の署名・未署名状態を維持します。今回の成功だけで全環境の実行許可を保証するものではありません。[署名方針](%E3%82%B3%E3%83%BC%E3%83%89%E7%BD%B2%E5%90%8D.md#署名対象の方針) と [調査記録](Smart%20App%20Control%E3%81%AB%E3%82%88%E3%82%8B%E8%B5%B7%E5%8B%95%E3%83%96%E3%83%AD%E3%83%83%E3%82%AF.md) に残しました。


## 9月9日：ヘッドレスエンジンの起動確認

途中の出力では Windows のアプリ実行制御による `0x800711C7` が発生したため、起動失敗時に子エンジンのログを示すようにしました。その後の最終出力の検証は成功しています。実行制御の設定や証明書ストアは変更していません。

## 9月6日：配布 ZIP の署名

提供元の既存署名を保持し、新たなコード署名は追加していません。ZIP の起動成功報告はありますが、Smart App Control による許可は利用環境によって異なります。調査と方針の移動先は [このフォルダーの目次](README.md) を参照してください。
