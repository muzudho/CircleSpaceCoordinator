## 失敗したこと・解決策にできなかったこと

- **自己署名を Valid にするだけ：** 信頼登録済みでも拒否された。SAC が信頼する提供元の証明書という条件と、ローカルの検証成功は別。
- **署名を外すだけ：** DLL の差替えと未署名 Release の両方で拒否された。
- **通常の Rebuild：** ビルド成功後に起動が拒否された。
- **ソリューション全体のクリーン、bin / obj の削除：** 一度の成功報告の後、10:47 に再発した。生成物の残存の切り分けには使えるが、実行許可の保証にはならない。
- **外部 DLL を含めて一括自己署名：** 外部 DLL が拒否された。現在は自作ファイルの許可リストだけを署名し、他人が作った DLL・EXE の署名・未署名状態を維持する。
- **隔離環境の証明書エラーを、そのまま PC の状態とみなす：** 隔離環境では証明書が見つからなかったり信頼エラーになったが、通常ユーザー環境では署名・検証できた。実行環境を分けて記録する。

## 過去の説明で訂正すること

- 「未署名なら必ずブロック」ではない。クラウドの安全性判定で許可される場合もある。
- 「自己署名を信頼登録すれば SAC 対策になる」とは案内しない。
- 「Visual Studio の再起動が効く」は成功報告に留め、原因を確定しない。
- `Unblock-File` は過去の会話で提案されたが、この事例での効果は検証していない。SAC の許可を保証する手順にはしない。
- 「SAC をオフにすると再有効化には必ず再インストールが必要」という過去の説明は、最近の Windows 更新を反映していない。実際の PC の条件を確認する。
- 自動署名あり／なしの一度の比較だけで因果関係を断定しない。署名でファイルの内容も変わり、クラウド判定を固定できないため、確認した条件と結果を記録する。
