# StationeryUI v0.3.0 → v0.5.0 移行計画

2026-09-27 調査。対象は CircleSpaceCoordinator の現在の実装。**移行作業は保留中。パッケージ更新や画面設定の変換は未実施。** 上流ドキュメントの内容をリポジトリー所有者が確認するまで、この計画を実行しない。確認結果を受けて、上流の v0.5.0 の仕様と計画を再照合する。

## 結論と移行単位

３つの NuGet パッケージを同時に v0.5.0 へ揃える。ただし作業は「旧版の比較基準」「新形式の試作」「依存関係とアダプター」「F12 開発者ウィンドウ」「実機確認」の順に区切る。イベント一覧以外の全画面を新しい JSON に作り直す必要はない。現状、それらの多くは文房具 UI のコントロール／座標型を直接利用し、設定ファイルで配置しているのはイベント一覧だけである。

旧 `models`／`bindings` の JSON を v0.5.0 にそのまま渡すことはできない。v0.5.0 のパーサーは `modelTree` を必須とし、旧セクションを明示的に拒否する。従来の設定を動かすための変換層を恒久的に増やさず、イベント一覧の原本を一度、新形式へ移す。アプリ固有の配置契約とリロード方針は保つ。

## 段階と完了条件

### 0. 比較基準を固定する

1. 作業用ブランチで現在の変更を保全し、v0.3.0 のビルド、Desktop／StationeryUI テスト、架空サンプルのイベント一覧、F12 の表示を記録する。ビルドは 2026-09-27 時点で `dotnet build CircleSpaceCoordinator.slnx --no-restore -v:q` が警告 0・エラー 0。
2. `EventStyleChecks` が比較する矩形（通常、コンパクト、行ひな型、F12 の表示座標）を移行前の期待値として保存する。画面のスクリーンショットを取る場合は架空データだけを使う。
3. 原本 `App_Doc/events.style-settings.md` とユーザーの `application-settings.json` の役割を確認する。ユーザー設定や実データを変換対象に含めない。

**完了条件：** 旧版の再現手順、比較値、失敗時に戻すコミットを記録できている。

### 1. 新しい画面設定の小さな試作を作る

1. v0.5.0 の同梱 JSON とパーサーを読み、`/events` 以下の `regular`／`compact`／`rowTemplate` を新しい `modelTree` と `viewports`／`controlTree` のどこで表現するか対応表にする。各操作の「アプリでの役割 → モデルパス → コントロールハンドル → 配置経路」を一行ずつ固定する。
2. まず `regular` の外枠、見出し、本文、操作欄だけを新形式で試作する。全要素を一括変換しない。v0.5.0 を参照する一時的な検証用プロジェクトかテストで `StationeryStyleSettings.Parse` と `StationeryLayoutEngine.Arrange` に通し、まだ v0.3.0 のアプリ本体で得た旧矩形と比較する。
3. `compact` と `rowTemplate` を追加する。通常／コンパクトの切替条件と繰り返し行の配置は C# で維持し、両方の配置が有効になるよう選択キーまたは別の配置計算で扱う。旧設定の行・列が 0 始まり、旧 binding のセルが 1 始まりだった点は、経路のセル記法へ写す際に明示的に照合する。
4. 原本のファイル名を `*.stationery-ui.json` に変更するかは、エディターで開けることと既存運用を確認して決める。現行の `.style-settings.md` は JSON として扱っており、単なる拡張子変更ではない。変更するなら埋め込みリソース名、Debug の絶対パス、文書とテストを同じ段階で更新する。

**完了条件：** 新原本を v0.5.0 が読み、少なくとも既存テストの全寸法で主要矩形、行高、操作ボタン位置が一致する。新形式の原本に旧 `models`／`bindings` を残さない。

### 2. ３パッケージとアダプターを同時に切り替える

1. ３つの PackageReference をすべて `0.5.0` に揃え、復元後にソリューションをビルドする。残る旧 API の参照はコンパイルエラーを一覧にして、型名だけの機械的置換で済むものと、動作の再設計が必要なものに分ける。
2. `EventListStyle` の旧 JSON 補正処理、`Models[0]`、`Bindings` の走査、ネストしたグループ矩形の補填を新契約に合わせる。原本の検証には必須ハンドル、パス、型、通常／コンパクト両方の配置、`eventRow` の正の高さを含める。`ControlBounds` を使う場合も、描画・クリック・F12 が同じ配置結果を参照する。
3. `EventListStyle` の「安定してから読み、検証後に採用」「不正な編集では前回の有効設定を維持」「アプリ設定の `styleAutoReload` が唯一の切替元」という動作を保持する。Release の埋め込み原本、Debug の原本監視、Revision による配置キャッシュ更新をそれぞれ確認する。
4. `CircleSpaceCoordinator.StationeryUI` の追加部品、`Desktop.Windows` の入力・テキスト・スクリーンショット・ボタン類について、コンパイルエラーと利用時の動作差分を処理する。アプリ側独自部品を上流パッケージと無関係に消さない。

**完了条件：** v0.5.0 だけで Debug／Release がビルドでき、Desktop と StationeryUI のテストが通る。イベント一覧で通常／コンパクト表示、クリック、スクロール、設定変更、異常 JSON の復帰を確認できる。

### 3. F12 とエディター連携を選んで接続する

1. まず既存の F12 子プロセスと `StationeryInspectorGame` が v0.5.0 で動くか確認する。捕捉クリックが背後の編集へ流れず、表示パスと座標が一致し、子ウィンドウを閉じても本体が残り、本体終了時に子が終了することを確認する。
2. v0.5.0 の `StationeryDeveloperWindow.UseEditor(...)` は追加機能として評価する。外部 `StationeryUIEditor.exe` を使う場合、配布方法、実行ファイルの探索、スタイル原本の渡し方、read／edit モード、未保存編集と外部変更の扱いを決める。既存 F12 の置換を必須前提にしない。
3. エディターが新原本を読み書きできるか、既存の独自拡張子を使う場合は特に確認する。自動保存で設定が変わるときも、アプリ側は検証済みの新設定だけを採用する。

**完了条件：** F12 の起動・選択・更新・終了が Debug／Release／publish 出力で動く。外部エディター方式を採用する場合のみ、その配布と失敗時の表示も検証済み。

### 4. 実機受入と文書の更新

1. 架空サンプルで Windows 実機のサイズ変更、小画面、0 サイズ相当、IME 入力、モーダル、アプリ非アクティブからの復帰を確認する。イベント一覧は通常／コンパクトの境界、クリック／ホバーと表示の一致、選択状態とスクロール維持を確認する。
2. `Docs/Dev/Version/1_13_0/StyleSettings/`、`Docs/User/Version/1_13_0/StyleSettings/event-list-style-settings.md`、`CircleSpaceCoordinator.StationeryUI/README.md`、`Desktop.Windows/README.md` に残る v0.2.0／旧形式の記述を現行実装に合わせて更新する。歴史的な記録は当時の記述として残してよいが、利用手順から古い API へ誘導しない。
3. 配布チェックで v0.5.0 の DLL とライセンス、設定原本の埋め込み／必要なコピー、別のカレントディレクトリからの起動を確認する。

**完了条件：** 自動テスト、Debug／Release ビルド、架空データでの GUI 操作、publish 出力をそれぞれ記録し、残る未確認事項を明示できている。
