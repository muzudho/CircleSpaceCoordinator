# Smart App Control：開発時の運用と調査記録

2026-09-26：Smart App Control をオフにする運用へ変更した。以下の旧運用・署名調査は当時の記録として残す。自己署名・自動署名・事前の全 `bin`・`obj` 削除は[廃止記録](../../../../Archive/RetiredSmartAppControl/README.md)を参照。現在のビルド・配布は[開発者向けガイド](../../../../README.md)と[リリース手順](../../%E9%85%8D%E5%B8%83/%E3%83%AA%E3%83%AA%E3%83%BC%E3%82%B9%E6%89%8B%E9%A0%86.md)を使う。

更新日：2026-09-12

**開発中は SAC をオフ、開発していないときはオンに戻す運用を採用する方針です。** 自己署名やクリーンビルドを、SAC の実行許可を得るための解決策として扱いません。設定の切替と再有効化は、この PC ではまだ実機確認していません。

## 以前の開発 PC 手順（廃止）

1. 初回は Windows Update を適用し、［Windows セキュリティ］→［アプリとブラウザー コントロール］→［スマート アプリ コントロールの設定］を確認します。再有効化できない旨の表示があれば、オン／オフを往復できる前提で進めません。
2. 開発を始めるときに SAC を［オフ］にします。Microsoft Defender のリアルタイム保護はオンのままにします。
3. Visual Studio でビルド・実行・デバッグします。SAC の設定と、プロジェクト独自の自動署名設定は別です。
4. 開発を終えたらアプリと開発用エンジンを終了し、SAC が［オン］に戻ったことまで確認します。開発 PC を普段使いするときもオンにします。
5. 配布前の起動確認は SAC をオンにして行い、開発時のオフでの成功とは別に記録します。

SAC のオフは PC 全体に影響します。このアプリだけの例外設定ではありません。最近の Windows 更新では再インストールなしで再有効化できると公式 FAQ に記載されていますが、すべての PC の状態で可能とは扱いません。[Microsoft：SAC FAQ](https://support.microsoft.com/ja-jp/windows/security/threat-malware-protection/smart-app-control-frequently-asked-questions)

この文書の整理では Windows の保護設定、証明書ストア、自動署名の既定値は変更していません。

## bin / obj の削除だけを行う

アプリ・エンジンを停止し、ほかのビルドが動いていない状態で、リポジトリーのルートから実行します。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Build\Clear-BuildOutput.ps1
```

ソリューション内の全プロジェクトの `bin`・`obj` を削除するだけです。その後、Visual Studio の実行ボタンでビルド・起動します。2026-09-12 には、この手順後にも SAC のブロックが再発しました。

`scripts/Build/Build.ps1` は削除後に復元・ビルドも行いますが、アプリは起動しません。Visual Studio のビルド／F5 自体には自動削除を組み込んでいません。

## 記録の扱い

「ビルド成功」「署名検証 Valid」「起動成功」は分けて記録します。開発者からの報告と、ログで直接確認した事実も区別します。診断 JSON やスクリーンショットの原本はローカルの `artifacts/debug-startup-check/` に保存し、公開文書には個人情報を除いた結果を記載します。

SAC の説明・調査・署名の知見はこのフォルダーへ追記し、ほかの文書はここへのリンクを使います。利用者への案内は [ユーザー向け手順](../../../../../User/Version/1_13_0/Troubleshooting/SmartAppControl/README.md)だけに絞ります。
