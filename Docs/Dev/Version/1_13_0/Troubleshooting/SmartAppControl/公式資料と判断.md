# 公式資料から分かったこと

確認日：2026-09-12。公式の仕様と、この PC で確認した結果を区別します。

## SAC の判定

SAC はクラウドによる安全性判定を利用し、判断できない場合に署名を確認します。未署名ファイルが必ず拒否されるわけではありません。個々のアプリだけを許可する例外設定はありません。[Microsoft：SAC FAQ](https://support.microsoft.com/ja-jp/windows/security/threat-malware-protection/smart-app-control-frequently-asked-questions#bkmk_unknown)

今回のログでは拒否対象とポリシーを確認できましたが、クラウドの内部の判定理由は取得できていません。

## 署名検証と SAC の信頼

コード署名は発行元と、署名後の改ざんの有無を確認する仕組みです。[Microsoft：コード署名の概要](https://learn.microsoft.com/ja-jp/windows/win32/seccrypto/cryptography-tools)

SAC 向けの説明では、信頼されたプロバイダーが発行した証明書だけが考慮され、RSA ベースの署名が必要とされています。ローカルの `Get-AuthenticodeSignature` が `Valid` であることだけでは、この条件を満たしたとは言えません。[Microsoft：SAC 向けコード署名](https://learn.microsoft.com/ja-jp/windows/apps/develop/smart-app-control/code-signing-for-smart-app-control)

この PC の開発用自己署名が `Valid` でも拒否されたことは、上の説明と整合します。ただし、その事実だけで今回の拒否理由をすべて特定できたわけではありません。

## 信頼されたルート証明書プログラム

このプログラムは認証局に監査、情報開示、失効対応などを要求します。開発者が自分の PC のルートストアに証明書を登録する操作で、プログラムの参加認証局になれるという説明ではありません。[Microsoft：プログラム要件](https://learn.microsoft.com/ja-jp/security/trusted-root/program-requirements)

同文書ではコード署名証明書を均等に扱う方針も説明されています。過去の会話にある「EV なら特に有利」という説明を、このアプリの SAC 対策として使用しません。技術要件の移行先も同ページに案内されています。

## オン／オフの切替

最近の Windows 更新では、再インストールせずに SAC を再有効化できると FAQ に記載されています。古い説明の「オフにすると必ず再インストールが必要」を一律に適用しません。一方、更新状況やデバイスの状態を確認せず、必ず戻せるとも案内しません。[Microsoft：SAC FAQ](https://support.microsoft.com/ja-jp/windows/security/threat-malware-protection/smart-app-control-frequently-asked-questions)
