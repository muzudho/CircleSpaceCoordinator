# リリース手順（CircleSpaceCoordinator 署名・配布コマンド）

配布方法の現在の方針は [配布に関する知見](README.md) を参照してください。本書は既存のローカル署名・ZIP 作成手順です。SAC の制限・署名・起動確認は [SAC の開発者向け資料](../Troubleshooting/SmartAppControl/README.md) にまとめています。

一般公開前には [情報点検と残作業](../public-release-review.md) を確認してください（旧リポジトリーの点検記録を含むため、現在の状態と照合してください）。ZIP作成時は `Test-PublicReleaseContent.ps1` が設定・業務ファイルなどの混入を検査します。この検査は、ソース履歴や署名情報まで公開可能と保証するものではありません。

以下のコマンドは、リポジトリのルート  
D:\github.com\muzudho\CircleSpaceCoordinator  
で PowerShell を開いて実行してください。  

## GitHub Release の先頭案内（毎回必須）

初めて見る利用者が配布ZIPを見つけられるよう、リリース本文の先頭には必ず GitHub の `[!IMPORTANT]` アラートでダウンロード案内を置きます（2026-09-15 利用者指定）。通常の太字だけで済ませず、次の形式を使ってください。

```markdown
> [!IMPORTANT]
> 通常の利用には、Assets の **[Windows x64用ZIP](そのリリースの配布ZIPへの直接リンク)** をダウンロードしてください。

`Source code` は開発者向けです。
```

公開前に、リンクのタグ・ZIP名が今回のリリースと一致することを確認します。公開後は本文を読み直し、`> [!IMPORTANT]` と案内文・リンクが保持されていることを確認してください。

## ZIPの作成

リリース前に [バージョン管理](バージョン管理.md) に従って `Directory.Build.props` の `Version` を更新します。ZIP 名には発行した EXE の製品バージョンが入ります。

通常の自己署名による社内・自分のPC向け配布では、次のコマンドだけでよいです。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\ForSmartAppControl\New-ReleaseZip.ps1"
```

このスクリプトは次を順に行います。

1. 期限内の開発用コードサイニング証明書を使う。なければ新規作成し、現在のユーザーの `Root` と `TrustedPublisher` へ信頼登録する。
2. DesktopアプリとProject CLIを `win-x64` 向けに発行する。
3. 発行された EXE/DLL のうち、このリポジトリで作成する署名対象だけに署名し、その署名状態が `Valid` であることを確認する。外部ライブラリは提供元のファイルをそのまま使用する。
4. Desktop配布フォルダー全体を、次の日時入りZIPとして作成する。

```text
artifacts\release\CircleSpaceCoordinator.Desktop.Windows-v1.0.0-win-x64-YYYYMMDD-HHMMSS.zip
```

ZIPには `CircleSpaceCoordinator.Desktop.Windows` フォルダーそのものが入るため、利用者はZIPを空フォルダーへ展開して、その中の `CircleSpaceCoordinator.Desktop.Windows.exe` を起動してください。作成後も、下記「ZIP作成前に起動を確認する」「ZIPを展開して最終確認する」は実施してください。

別のランタイム向けに作る場合は、例えば次のように指定します。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\ForSmartAppControl\New-ReleaseZip.ps1" -RuntimeIdentifier win-x64
```

認証局発行の証明書など、既存の証明書を明示的に使用したい場合は `-CertificateThumbprint` を付けます。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\ForSmartAppControl\New-ReleaseZip.ps1" -CertificateThumbprint "YOUR_CERTIFICATE_THUMBPRINT"
```

以下は、証明書や署名状態を個別に確認したい場合の手動手順です。

## 【1. 開発用証明書の拇印を確認する】

```powershell
Get-ChildItem Cert:\CurrentUser\My -CodeSigningCert |
  Where-Object Subject -eq 'CN=CircleSpaceCoordinator Development Code Signing' |
  Select-Object Subject, Thumbprint, NotAfter,
    @{ Name = 'Status'; Expression = { if ($_.NotAfter -gt (Get-Date)) { 'Valid' } else { 'Expired' } } }
```

`Status` が `Valid` の行だけを使用し、その `Thumbprint`（40桁）を手順3で使用します。  
`Expired` と表示された証明書は使用しません。  
何も表示されない、または `Expired` しか表示されない場合は手順2へ進みます。

## 【2. 開発用証明書を作成・信頼登録する】

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\ForSmartAppControl\New-DevelopmentCodeSigningCertificate.ps1"
```

このコマンドは、証明書がなければ作成し、すでにあればその証明書を再利用します。  
いずれの場合も、証明書を現在のユーザーの `Root` と `TrustedPublisher` へ信頼登録します。

**新しいリリースを作る前、または署名状態が `UnknownError` になったときは必ず実行してください。** 自己署名証明書が `My` にあるだけでは Windows に信頼されず、EXE が起動しないことがあります。

作成結果に表示された `Thumbprint` を手順3で使用します。表示を閉じた場合や確認し直したい場合は、手順1のコマンドをもう一度実行してください。

### 信頼登録の確認

手順1で確認した拇印を `YOUR_CERTIFICATE_THUMBPRINT` に入れて、`Root` と `TrustedPublisher` の両方に同じ証明書があることを確認します。

```powershell
$thumbprint = "YOUR_CERTIFICATE_THUMBPRINT"
'Cert:\CurrentUser\Root', 'Cert:\CurrentUser\TrustedPublisher' |
  ForEach-Object {
    Get-ChildItem $_ | Where-Object Thumbprint -eq $thumbprint |
      Select-Object PSParentPath, Subject, Thumbprint, NotAfter
  }
```

2行表示されれば正常です。何も表示されない、または片方しか表示されない場合は、手順2のコマンドをもう一度実行してください。

## 【3. 署名付き配布物を作成する】

次の YOUR_CERTIFICATE_THUMBPRINT を、手順1で表示された40桁の拇印へ置き換えてください。  

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\ForSmartAppControl\Publish-AndSign.ps1" -CertificateThumbprint "YOUR_CERTIFICATE_THUMBPRINT" -RuntimeIdentifier win-x64
```

このコマンドは、次の2つの古い出力フォルダーを削除してから作り直します。必要なファイルを出力フォルダー内で直接編集・保存しないでください。

- `artifacts\signed\CircleSpaceCoordinator.Desktop.Windows`
- `artifacts\signed\CircleSpaceCoordinator.ProjectCli`

各フォルダー内の `.exe` と `.dll` のうち、`Sign-ReleaseArtifacts.ps1` の明示的な許可リストにある自作アセンブリだけを署名します。MonoGame、SDL2、StationeryUI などの外部ライブラリには署名せず、提供元の署名・未署名状態を維持します。自作の `CircleSpaceCoordinator.StationeryUI` は署名対象です。
いずれかの署名または検証に失敗した場合は、スクリプトがエラーで停止します。

## 【4. 配布するフォルダー】

```text
artifacts\signed\CircleSpaceCoordinator.Desktop.Windows
```

Desktop アプリを使用する場合は、このフォルダーを丸ごと（あとで） ZIP にしてください。  
EXE だけを取り出すと `SDL2.dll` などを読み込めず、アプリが起動しません。

コマンドラインツールも配布する場合は、別に次のフォルダーを丸ごと（あとで） ZIP にしてください。

```text
artifacts\signed\CircleSpaceCoordinator.ProjectCli
```

## 【5. 署名を確認する】

Desktop 配布物にあるすべての EXE/DLL の署名状態を確認します。

```powershell
Get-ChildItem ".\artifacts\signed\CircleSpaceCoordinator.Desktop.Windows" -Recurse -File |
  Where-Object Extension -in '.exe', '.dll' |
  Get-AuthenticodeSignature |
  Group-Object Status |
  Select-Object Name, Count
```

自作の署名対象は `Valid` であることを確認してください。外部 DLL は未署名のものもあるため、全体に `NotSigned` が含まれること自体は署名処理の失敗ではありません。外部 DLL に自己署名を追加して解消しないでください。過去の一括署名済み出力を再利用する場合は、外部 DLL を提供元のファイルへ戻すか、新しい出力フォルダーへ publish してください。

## 【6. ZIP作成前に起動を確認する】

次のファイルをダブルクリックし、ウィンドウが起動することを確認します。

```text
artifacts\signed\CircleSpaceCoordinator.Desktop.Windows\CircleSpaceCoordinator.Desktop.Windows.exe
```

初回起動時は、Windows による署名・セキュリティ検査や .NET／MonoGame の初期化などにより、  
ウィンドウが表示されるまで 20秒 程度かかることがあります。  
すぐに表示されなくても慌てずに待ち、EXE を何度もダブルクリックしないでください。  
2回目以降は1秒程度で表示されることがあります。

### 起動ログの場所

アプリがプロジェクトを選択・読込した後、解凍したアプリフォルダー直下に操作ログを作成します。

```text
CircleSpaceCoordinator.Desktop.Windows\logs\ui-operations-YYYYMMDD-HHMMSS.jsonl
```

ウィンドウも表示されず `logs` フォルダーも作られない場合、アプリはログ初期化より前で停止しています。ZIPを作り直す前に、次を確認してください。

1. 手順5で自作の署名対象が `Valid` であること（外部ライブラリーの `NotSigned` は許容します）。
2. `UnknownError` の場合は手順2を実行して、自己署名証明書を信頼登録してから手順3へ戻ること。
3. EXE単体ではなく、`CircleSpaceCoordinator.Desktop.Windows` フォルダー全体を使用していること。

## 【7. ZIPを展開して最終確認する】

手順6で確認したフォルダー全体を ZIP にし、**新しい空フォルダー**へ展開します。  
展開先の次の EXE をダブルクリックして、ウィンドウの起動と `logs` フォルダーの作成を確認してください。

```text
（展開先）\CircleSpaceCoordinator.Desktop.Windows\CircleSpaceCoordinator.Desktop.Windows.exe
```

ここで起動しない場合は、ZIPの中身を一部だけ取り出していないかを確認し、展開先ではなく元の `artifacts\signed\CircleSpaceCoordinator.Desktop.Windows` に対して手順5を再実行してください。

確認後、`CircleSpaceCoordinator.Desktop.Windows` フォルダーを丸ごと ZIP にします。古い配布フォルダーへ一部のファイルだけを上書きせず、毎回新しく生成されたフォルダー全体を使用してください。

## 【8. 利用PCでツールを更新する】

v1.12.1以降は、設定を `%LOCALAPPDATA%\CircleSpaceCoordinator` に保存します。`application-settings.json` にはイベント一覧・表示状態・作業者など、`space-definitions.json` には共通スペース定義が入ります。同じWindowsユーザーならZIPの展開先を変えても共通の設定を使うため、通常の更新で設定をコピーする必要はありません。イベント本体のJSONは別ファイルです。

1. 古い版のアプリを終了します。
2. 新しいZIPを、古い版とは別の新しい空フォルダーへ展開します。
3. **v1.12.0以前から初めて更新するときだけ**、新しい保存先にまだ設定がない場合は、古いEXEの隣の `application-settings.json` と `space-definitions.json`（存在するもの）を新しいEXEの隣へコピーします。初回起動でユーザーフォルダーへ移行し、元ファイルは残ります。移行先にある設定は上書きしません。
4. 新しいEXEを起動し、従来のイベント一覧と既存イベントを確認します。
5. 業務で問題なく使えることを確認するまで、古いフォルダーは残します。

EXE・DLL・ログは旧版からコピーしません。旧設定がない場合でも、既定のプロジェクト保存フォルダー直下に有効なイベントJSONがあれば一覧へ登録します。別の場所にあるイベントは［既存ファイルを登録］で指定してください。設定の詳しい保存先と移行条件は [アプリケーション設定ファイルについて](../設計/アプリケーション設定ファイルについて.md) を参照してください。

## 【補足】

-ExecutionPolicy Bypass は、この powershell.exe の実行だけに適用されます。  
Windows全体や現在のユーザーの実行ポリシーは恒久変更しません。  

開発用の自己署名証明書は、作成したPC以外では通常信頼されません。  
現在は、証明書を作成・信頼登録した自分の PC 内での動作確認に使用します。一般配布では、認証局発行のコードサイニング証明書や、条件を満たした後の SignPath Foundation などを使用してください。
