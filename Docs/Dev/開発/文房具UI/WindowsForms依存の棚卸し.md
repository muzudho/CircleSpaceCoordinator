手動確認対象は、各入口での確定・取消、空白名、IME 確定、作成・複製先への選択移動、Undo。GUI の実機確認は未実施。

## クロスプラットフォーム化との境界

直接の Windows.Forms 参照は Windows 実行プロジェクトに集まっている。同プロジェクトは `net10.0-windows` / `UseWindowsForms=true` のまま。また、文房具 UI の入力には `StationeryUI.Windows` の `WindowsTextInputService` を使用している。フォームを置き換える作業と、IME・クリップボード・文字描画などの OS 接続を別ホストへ移す作業は、両方必要になる。今回の変更だけで他 OS で起動できるわけではない。

## 引継ぎ用の実装計画（2026-09-14）

以下は未実装の計画。上の「今回の移行」に記載した名前入力の移行のみ実装済み。過去の [調査結果と実装計画](調査結果と実装計画.md) は履歴として扱い、今後の着手順・対象は本節を基準にする。新しい担当者は作業開始時にソースと照合し、各段階の状態を更新する。

### 目標・対象外・完了の定義

目標は、ファイル選択を除くアプリの入力・選択・閲覧・通知・進捗を、同じ MonoGame ウィンドウ内の文房具 UI へ移すこと。編集・保存形式・配置判定の仕様は既存サービスを維持し、画面の置換に必要な変更を中心に進める。

ファイル選択、ファイルの読込み・保存処理の作り直し、他 OS 用ホストの実装はこの計画の対象外。取込み・書出しに付随する列選択や進捗は対象に含める。IME・クリップボード・文字描画の OS 接続は境界を維持し、他 OS 対応の残作業として記録する。

移行完了は、対象の通常操作・エラー経路に Windows フォームが開かず、旧フォームと呼出しが撤去され、関連テストと手動確認の結果が記録された状態とする。`UseWindowsForms` の削除や他 OS での起動成功は別の達成項目。ネイティブのファイル選択に必要な依存を無理に削除しない。

### 実装の共通ルール

- 表示は即座に戻り、確定・取消をコールバックまたは状態遷移で受ける。`ShowDialog()` の代わりにゲームスレッドで待機しない。`dialog_opened` と処理成功のログを区別する。
- 入力中は下書きだけを変更し、確定後に既存コマンドを実行する。取消時はプロジェクト・設定・Undo 履歴を変更しない。既存の Undo 対象操作は、一回の確定で一回の Undo を維持する。
- 開く時点の対象 ID・選択範囲を保持し、確定時に対象の存在を再確認する。処理中のイベント切替・終了にも対応し、古い画面の結果を別プロジェクトへ適用しない。
- 背後の入力遮断、押下キー・クリックの解放待ち、IME の Enter/Escape、フォーカス移動は既存モーダルに合わせる。検証エラーでは下書きを保持する。別の通知を開いて編集中の状態を失わない。
- 汎用の入力・選択・スクロール状態は OS 非依存にする。会場固有の下書き・検証は `CircleSpaceCoordinator.Desktop.Core/Interaction/`、ゲームへの接続は `VenueEditorGame` の機能別 partial ファイルに置く。以下で述べる新しい部品は設計案であり、既存 API 名ではない。
- 文房具 UI は現在 NuGet パッケージから利用している。互換用の `CircleSpaceCoordinator.StationeryUI` に旧ライブラリーを再コピーしない。既存パッケージの API を確認して再利用し、不足する汎用機能は StationeryUI 本体への追加・テスト・固定バージョン更新を作業として切り出す。別リポジトリーへの絶対パス参照を追加しない。

### 1：番号・番地入力

対象：`VenueEditorGame.TextInput.cs`、`VenueEditorGame.cs` と `VenueEditorGame.NumberChannels.cs` の `DeskNumberDialog.Show` および一括上書き確認。

`OpenUnderlineInput` と `ConfirmUnderlineInput` は名前の必須入力を前提にしている。入力ごとの空欄許可・最大長・検証メッセージを渡せるようにし、既定値は従来の名前入力のままにする。番号は旧フォームの 80 文字制限と空欄削除を維持する。確定した空文字と取消を別の結果として扱う。

複数の異なる値への上書きは、まず画面内で確認し、同意したときだけ下線入力へ進む。初期選択は取消側にする。対象範囲は開いた時点で保持し、既存の一括更新コマンドへ接続する。

完了条件：単一編集、一括編集、空欄削除、確認の否定、入力の取消、Undo/Redo が維持される。名前入力では引き続き空白名を拒否する。両方の呼出し元を移して `DeskNumberDialog.cs` を撤去する。

### 2：配置選択・紐付け・コピー

既存の一覧 UI を調べ、単一選択・スクロール・キーボード移動の共通部分を再利用する。表示名ではなく ID で選択を保持し、同名項目や長い名前でも選べるようにする。選択肢が空の場合は確定を無効にし、理由を表示する。

`LayoutBindingDialog` は用途ごとのタイトル・説明・初期選択を維持して、`VenueEditorGame.cs` 内の全呼出しを移す。紐付け変更の収容可否は既存サービスで判定し、失敗時は紐付けと選択を変更しない。

`PlanCopyDialog` はコピー元・先の二つの選択を持つ下書きにする。同じ ID の組合せを拒否し、候補が二件未満なら実行できない理由を表示する。現行のコピー方法は「フレーム配置だけコピー」一種類なので、方法の追加はせず、説明として示してよい。コピー先のサークル配置を保ち、収まらない場合は変更なしで通知する。

`ExportPlanDialog` は書出し対象の選択だけを移す。選択後のネイティブファイル選択・既存の書出しフローへ結果を渡し、どちらで取り消しても書出さない。

完了条件：同名・長い名前・大量候補・候補なしで操作できる。現在と同じ選択や取消で不要な編集を起こさず、紐付け・コピーの失敗時にデータが変わらない。三つの旧ダイアログを撤去する。

### 3：正規表現・チャンネル設定

複数の下線入力欄と選択欄を持つ画面を用意し、Tab/Shift+Tab、クリック、IME の入力先を一つのフォーカス状態で管理する。名前入力用の単一 `underlineEditor` に場当たり的に欄を追加しない。

正規表現設定はパターン・置換文字列と既存の検証・表示例を移す。空パターンで元の ID を表示する動作、確定時の設定保存、取消時の設定維持を保つ。不正パターンでは欄の近くにエラーを表示し、修正できる状態を残す。

チャンネル設定は名前・取込み列の選択を移す。「番地」を通常チャンネル名に使えない規則、「対応なし」、取込み列がない場合の案内を維持する。削除確認と `ShowChannelError` も画面内へ移す。

セルの重みは数値入力と増減操作を用意する。現行の範囲 0～1、小数点以下6桁、増減幅0.1を基準にし、不正文字・範囲外の確定を拒否する。選択範囲への適用は既存コマンドを使う。

完了条件：複数欄間で文字や未確定の IME 入力が混ざらず、取消・検証失敗で設定やチャンネルを変更しない。重みの境界・一括更新・Undo を確認し、二つの旧ダイアログを撤去する。

### 4：セル全文の閲覧

`ShowParticipantCell` の閲覧専用フォームを、文房具 UI の閲覧画面へ置換する。行・列・見出しと値を渡し、複数行・長い一行・空文字を表示する。縦横スクロール、文字の選択、全選択・コピーを提供し、編集コマンドを接続しない。OS クリップボードは既存の入力サービス境界を使う。

完了条件：長文の末尾まで読め、選択した部分をコピーでき、元データは変化しない。画面外までテキストを縮小するだけの実装で済ませない。リサイズ後も表示とヒット判定が一致する。

### 5：非同期処理の画面接続

既存の最適化進捗を参考に、未開始・実行中・成功・失敗の状態をゲーム側で扱う。既存のファイル処理はワーカーで実行し、結果の UI 反映とワークスペース更新はゲームの Update 側に戻す。GPU・文房具 UI の状態をワーカーから変更しない。

開始操作の二重実行を防ぎ、例外を必ず回収する。処理中は入力を遮断しつつ描画を継続する。処理がキャンセルを実装していない場合は、停止できるボタンを表示しない。特に書出しを途中で強制終了しない。終了要求時に結果をどう回収して終了するかを決め、処理完了前に必要なリソースを破棄しない。

完了条件：遅い処理でもアニメーション・リサイズが動作し、成功・例外が一度だけ反映される。処理中の終了要求、二重開始、異なるイベントへの結果混入を検証する。

### 6：取込み・書出し設定

まず `ParticipantImportForm.ShowImport` と `CircleSeatExportForm.ShowExport` を、ネイティブファイル選択、ファイル処理、設定画面に分離する。ファイル選択は Windows のアダプターへ残し、設定画面にはパスと読込み結果を渡す。フォームの `owner` や `DialogResult` を共通の下書き・処理層へ持ち込まない。

取込みは「ファイル選択 → 読込み中 → 文字コード・シート・列対応とプレビュー → 既存の確認 → 取込み → 結果」の流れにする。文字コード変更時の再読込みにも5の状態管理を使う。途中のプレビュー更新でワークスペースへ取り込まない。必須・任意列の扱いと既存の文字コード判定・警告を移す。表は既存の `ParticipantTableView` を再利用できるか確認し、表示範囲中心に描画する。

書出しは「配置選択 → ファイル選択 → 読込み中 → シート・列対応 → 書出し中 → 結果」とし、実際の既存入口の分岐を確認して接続する。更新行数・見つからないサークル ID 件数を維持する。対象外行を書き換えない条件、ファイル履歴・前回ディレクトリーの保存タイミングも現行動作と照合する。

完了条件：ファイル選択・設定の各取消、文字コード再読込み、複数シート、重複見出し、列未選択、不正ファイル、使用中ファイル、処理失敗を確認する。確定前に参加者データや出力ファイルを変更せず、成功時の件数が既存処理と一致する。両フォームと利用元がなくなった `LoadingSpinnerDialog` を撤去する。

### 7：起動時エラーと残存参照整理

`Program.StartEngines` はゲーム起動前にエンジンを起動しているため、`MessageBox` を単純に `ShowInAppMessage` へ置き換えられない。ワークスペースなしで起動できる文房具 UI の画面を先に用意し、エンジン起動中・起動失敗・通常画面への移行を管理する。`EditorConnection.Current` を必要とする初期化の順序を確認し、成功後に通常のイベント選択へ進める。再試行機能の追加は必須にせず、失敗理由と終了操作を提供する。

描画ウィンドウ自体の初期化失敗は同じ画面に表示できないので、ログなどで診断できるようにする。これは文房具 UI の表示成功として扱わない。`EngineRuntime` の終了・破棄も起動成功／失敗の双方で確認する。

最後に全ソースで Windows.Forms と `ShowDialog` / `MessageBox` を再検索し、通常画面・失敗経路に残ったものを移す。`Program.cs` の Forms 初期化はファイル選択に必要かを確認して Windows のファイル選択側へ集める。`UseWindowsForms`、`STAThread`、`StationeryUI.Windows` は一括削除せず、用途別に残存理由を記録する。

完了条件：エンジン起動失敗をゲーム画面で表示でき、通常の起動・終了も成立する。残す直接参照はファイル選択とそれに必要な接続に限定され、そのファイル名・用途が本書に列挙されている。パッケージ経由の OS 依存は別の残存一覧として明示する。
