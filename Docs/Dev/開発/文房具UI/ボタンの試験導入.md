# ボタンの試験導入

## 今回の変更

ツールバーのモード切替・アイコンボタンを、`CircleSpaceCoordinator.StationeryUI/Controls/StationeryButtonRenderer.cs` の共通描画へ接続した。

囲碁側の `Presentation/StationeryUI/Controls/Button/Button.cs` の背景・枠・影・状態別の色を移植し、MonoGame 型と `KfwStationeryDrawingTools` への依存を、既存の `ScreenRectangle` と描画コールバックへ置き換えた。文字ラベル専用だった内容描画はコールバックとし、既存のアイコンも描けるようにした。移植元の MIT ライセンスは `CircleSpaceCoordinator.StationeryUI/ThirdParty/KifuwarabeGo2026-LICENSE.txt` に保存している。

`IconButtonModel` のクリック・押下・選択・有効状態の管理は引き続き使用する。押下時の 2 ピクセル移動も維持する。選択ボタンの枠と内側の線を強調し、無効ボタンの影を薄くして内側の光る線を描かなくした。

## アイコンの再利用

`Desktop.Windows/VenueEditorGame.cs` の `DrawToolbarIcon` が、机・手・フォルダー・カメラなどの線・図形を描いている。その処理を変更せず、新しいボタンの内容描画として呼び出している。モード切替の文字も既存の描画を使う。アイコン画像の作り直しや資産のコピーは不要だった。

## 今回の範囲

ツールバーは元から MonoGame 画面内の UI であり、今回の変更によって Windows フォームの個数が減ったわけではない。まず既存アイコンを文房具ボタンへ接続できる構造を試した。Windows ダイアログ内のボタン、右側の配置案操作ボタンなどは次の作業対象。

## 手動確認の手順

1. アプリを起動し、架空サンプルで各モードを切り替える。
2. 机・手・カメラなどのアイコンが欠けず、選択状態が見分けられることを確認する。
3. ボタンを押して外へドラッグして離すと実行されず、内側で離すと実行されることを確認する。
4. 無効状態のボタンが反応せず、ウィンドウのリサイズ後も表示位置とクリック位置が一致することを確認する。
5. Discord でアプリのウィンドウを共有し、受信側からアイコンと状態変化を確認する。

2026-09-06 の自動確認では、Release のソリューションビルドが警告・エラー 0 件で成功し、StationeryUI の既存テスト 7 件、Desktop の既存テスト 44 件が成功した。変更前後の `DrawToolbarIcon` のソースが一致すること、本文書群のローカルリンクが存在することも確認した。これらは新しい外観の見た目を検証するものではない。
