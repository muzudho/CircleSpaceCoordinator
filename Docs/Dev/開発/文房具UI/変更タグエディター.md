# 変更タグエディターの共通コンポーネント案

更新日：2026-09-19

## 目的と状況

[マルチユーザー共同編集計画](../../設計/マルチユーザー共同編集計画.md) の「誰が・いつ・何を変更したかを記入して画面を閉じる」操作を、文房具 UI の共通コンポーネントにする。他のアプリでも、同じ外観と操作で変更内容を記録できるようにする。

名称案は［変更タグエディター］、内部名案は `ChangeTagEditor`。本書は設計案であり、この複合コンポーネントの実装・パッケージ公開・アプリへの接続は未実施。

文房具 UI の独立リポジトリーでは、`StationeryUI.MonoGame.Controls.SinglelineTextUnderline.SinglelineTextUnderline` が下線表示と付属バッジを、`ActionBadgeComponent` がアクション名の表示を担当している。既存のバッジはホバー時の案内であり、単体ではクリック処理や入力確定を持たない。これらを組み合わせ、変更タグ用の入力状態と終了条件を追加する。このアプリが現在参照する `StationeryUI` 0.1.1 に必要な部品がすべて含まれるかは、導入時に別途確認する。

## 外観と操作

上段に変更者・変更日、その下に１行チェンジログの下線テキストと `(change)` バッジ、右下に［閉じる］を置く。

```text
  by むずでょ since 2026-09-19
  色が同化しているので変えた       (change)
  ──────────────────────────────
                                 13 / 1000

                                   閉じる
```

この例は今回の入力が有効な状態。文字数は保存対象の文章について数える。未入力では下線上に `変更内容を１０００文字で入力してください` を表示する。常設ラベルまたはアクセシブル名を［１行チェンジログ］とし、入力後も欄の用途が分かるようにする。

- 下線テキストをクリックすると、その場で文章を編集する。バッジをクリックしても同じ入力にフォーカスする。
- `(change)` は「この文章を編集する」という操作案内とする。変更済み・保存済みを表す状態バッジにはしない。
- バッジは既存のホバー表示に加え、キーボードでフォーカスしたときにも表示する案とする。表示の有無で配置が動かないよう、右端に領域を確保する。
- Tab で入力欄と［閉じる］を移動する。バッジは入力欄と同じ操作なので、別の Tab 停止位置を増やさない。
- 文字入力や入力欄からのフォーカス移動では、画面を閉じず、変更タグを確定しない。［閉じる］の操作で確定を要求する。
- 日本語 IME の Enter は変換確定として扱い、その操作で画面を閉じない。入力欄での Enter から画面終了へ自動的に進めない。
- 長文は１行のまま横スクロールして編集する。1000文字を小さく縮めて１画面に詰め込まない。バッジと文章・キャレットが重ならないようにする。
- 閉じられない理由を入力欄の近くに文字で表示する。色だけで有効・無効を伝えない。

前回の変更タグは読み取り専用で表示し、今回の入力欄とは分ける。変更なしなら前回のタグだけを表示し、ログを要求しない。変更が発生したら今回の入力欄を示し、前回の文章を今回の入力済み内容として流用しない。

前回と今回を併記する場合は、既存計画の `(by 一郎 since 2026-09-18) (by 二郎 since 2026-09-19)` を用い、それぞれ前回・今回と分かるラベルを添える。狭い画面では段を分ける。下線入力の本文は１行のままとする。

## 共通の状態と確定手順

| 状態 | ［閉じる］と記録 |
| --- | --- |
| 内容の変更なし／すべて元に戻した | 有効。入力不要、変更タグは更新しない |
| 内容の変更あり、ログが無効 | 無効。入力を保持して修正理由を表示 |
| 内容の変更あり、ログ・作業者・作業日が有効 | 有効。今回の変更タグとともに確定を要求できる |
| 確定・保存中 | 無効。二重実行を防ぐ |
| 保存失敗 | 画面を維持。入力とエラーを表示し、再試行可能にする |

このアプリでは前後空白を除いた1〜1000 Unicode スカラー値の１行を有効とする。空白だけ、改行、不正な Unicode を認めない。上限超過を黙って切り捨てない。Handle は最大16文字。既存下線入力の UTF-16 単位の上限をそのまま流用せず、同じ検証規則を UI と保存境界で使う。

共通部品は終了可否を公開し、［閉じる］と Esc・画面移動・通常終了を、ホストが同じ確定要求へ接続する。ボタンの無効化だけで終わらせない。Esc を取消・保存なし終了へ割り当てる既存ダイアログの動作は、このコンポーネントには流用しない。

確定要求時点の作業者・作業日・入力を１つの値としてホストへ渡す。ホストが内容とタグの保存に成功した場合だけ画面を閉じる。失敗時は前回の確定済みタグを維持する。日付が変わる場合も、画面表示と今回記録する日付を一致させる。

## 再利用の境界

| 文房具 UI が担当 | 利用アプリが担当 |
| --- | --- |
| 前回・今回のタグ表示、下線・バッジ・入力・フォーカス | 編集対象の識別と実際の内容の変更検出 |
| ログの検証、文字数表示、確定可能状態 | 作業者設定・作業日の供給 |
| 確定要求と処理中・失敗状態の表示 | 内容とタグの保存、オートセーブ、下書き復元 |
| 共通の終了可否の判定 | 全画面終了経路への判定接続 |
| 表示文言・上限などの設定受取り | パッケージ、Undo/Redo、Git などとの接続 |

共通部品は会場・ジャンル・パッケージの型を参照しない。入力として「前回の変更タグ」「今回の作業者と作業日」「内容が変更されたか」「表示文言・検証設定」を受け取り、出力として「確定可能か」「確定要求時の変更タグ」を返す。具体的な API 名は実装時に定める。

状態と検証は OS・描画に依存しない層へ、下線・バッジ・ボタンの描画は文房具 UI の描画層へ置く。IME・クリップボードは既存の OS 入力境界を使う。ホストが正しく変更検出・保存を接続して初めて、共同編集用の一連の操作が成立する。

各アプリで文字数や表示言語を設定できる構造にするが、本アプリの1000文字・指定プレースホルダー・日付精度は共同編集計画の仕様を守る。別アプリへの汎用化のために、本アプリの入力必須条件を緩めない。

## 導入順序と確認

1. 文房具 UI 側に状態・検証と下線入力＋バッジの複合部品を追加する。複数アプリから同じ版を参照できるパッケージとして提供する。
2. 本アプリのジャンルコードの網掛け編集へ接続し、作業者・日付・変更検出・保存・終了経路を連動させる。
3. 他のパッケージ項目の編集画面へ適用する。複数項目を変更する画面ではホストが対象を明示し、変更した項目だけにタグを付ける。
4. 別アプリまたはドメインに依存しないサンプルでも、同じクリック・Tab・IME・終了操作が成立することを確認する。

検証には、バッジと本文のクリックが同じ入力に入ること、ホバーなしのキーボード操作、1000文字の横スクロール、Unicode 上限、IME 確定による誤終了の防止、未入力での終了防止、変更取消後の入力不要化、保存失敗・再試行を含める。保存先やパッケージのないサンプルでも部品単体を試せるようにする。
