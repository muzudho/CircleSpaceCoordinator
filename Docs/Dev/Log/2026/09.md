# 開発日誌：2026年9月

Excel を中心とした配置作業を、画面上で編集・比較できる Windows アプリへ移す開発を進めています。今月は会場編集と Excel 入出力を整え、GitHub での配布を開始しました。画面共有中も操作を追いやすくするため、アプリ画面内に表示する「文房具 UI」への移行にも取り組んでいます。

新しい記録から順に掲載しています。記述は各日付時点の状況です。

## 9月26日：初回起動の作業者名入力とプロフィール画面

作業者名が未設定の起動時に［ユーザー・プロフィール］を表示して入力を求めるようにした。画面最上段から後で名前を変更でき、プロフィールのボタンから現在のユーザー設定フォルダーを開ける。既存の `handle` 設定を使い、空の名前は GUI から保存できないようにした。

入力画面には現在の Unicode 文字数と上限を `2/16` の形式で表示する。初回入力の確定後はプロフィールを閉じ、イベント一覧へ進むようにした。

Windows アプリの Release ビルドは警告・エラー 0 件。Desktop テストは 112 件中 111 件成功し、イベント一覧スタイルの再読込みテスト 1 件がレイアウトツリー重複のエラーで失敗した。この変更に関する GUI 実機操作は未確認。

## 9月26日：自己署名とビルド前の全出力削除を廃止

Smart App Control をオフにする運用へ変更した。Debug ビルド後の自動署名、開発用証明書の作成、Release の署名、およびビルド・publish 前に全プロジェクトの `bin`・`obj` を削除する処理を廃止した。旧スクリプトと手順は[廃止記録](../../Archive/RetiredSmartAppControl/README.md)に保存した。

現行のビルドは通常の `dotnet build`、配布は署名なしの publish と ZIP 作成を行う。配布内容検査は継続し、同梱する StationeryUI のライセンス文も原本とのハッシュ一致を確認する。Release ビルドは警告・エラー0件、配布内容検査のテストは12件成功し、署名なし ZIP の作成と内容検査を確認した。GUI の起動確認は別途行う。

## 9月21日夜～22日未明：イベント一覧のスタイル設定と F12 開発者ウィンドウ

文房具 UI のスタイル設定をイベント一覧へ導入し、配置の微調整を C# の変更なしで行えるようにしました。続いて、文房具 UI が提供する開発者ウィンドウを F12 から開けるように接続しました。利用者から、オートリロードと開発者ウィンドウの表示が実機で動作したとの報告がありました。

### 配置・寸法・余白を Git 管理する

見出し、説明、一覧と操作欄、ボタン、下部案内、一覧行のひな型をスタイル設定へ移しました。文房具 UI の配置エンジンが返す矩形を、既存の描画とクリック判定で共有します。操作欄の高さが足りない場合は、通常の1列配置からコンパクトな2列配置へ切り替えます。データ操作・画面遷移・色・フォントなどは引き続き C# が担当します。

原本は [App_Doc/events.style-settings.md](../../../../App_Doc/events.style-settings.md) に置きました。拡張子は利用者の指定で `.style-settings.md` ですが、内容は文房具 UI の JSON です。Markdown の見出しやコードフェンスは付けません。当初のユーザー設定フォルダーへ展開する方式から、Git 管理できる原本を直接編集する方式へ変更しました。

Debug ではビルド時に記録した原本の絶対パスから読み込み、Release ではその原本を C# アセンブリーへ埋め込みます。Release は外部スタイルファイルを必要とせず、原本への変更を配布へ反映するには再ビルドします。

### オートリロードと作業状態を両立する

イベント一覧にオートリロードの有効／無効ボタンを追加し、選択を `application-settings.json` の `styleAutoReload` に保存します。保存に失敗した場合は切り替えを確定しません。Release では埋め込み設定を使うため、ボタンは開発時専用であることを表示して無効にします。

監視は約500ms間隔で行い、同じ変更内容を2回読めた後に解析・画面固有の検証を通して採用します。無効中は配置を維持し、再有効化後に最新の設定を読みます。不正な JSON や必須モデルの欠落では直前の正常な配置を保持してエラーを表示し、初回の読み込み失敗では埋め込み設定を使います。原本を自動で作成・上書きする処理はありません。

ウィンドウ寸法に加えて設定の更新番号でも配置キャッシュを更新し、選択とキーボードフォーカスを維持します。配置が動いたときは押下中のボタンを解除し、誤操作を防ぎます。[利用方法と調整項目](../../../event-list-style-settings.md) をまとめました。

### 既存の開発者ウィンドウを接続する

文房具 UI の利用者向け・開発者向けドキュメントに組み込み方法がありました。既存の `StationeryDeveloperWindow` と `StationeryDeveloperView` を使い、アプリ側には別プロセス用の起動入口、デモを基にした MonoGame ホスト、検査情報の受け渡しを追加しました。独自の Id 一覧 UI は作っていません。

F12 で Id・完全パスの階層と、表示状態・位置・寸法を確認できます。開発者ウィンドウの F12／Esc で隠し、本体の F12 で再表示します。閉じるボタンで終了した場合は次の F12 で再作成し、本体の終了時には所有する子プロセスも終了します。検査用の起動では通常画面や編集・思考エンジンを起動しません。

現在の登録対象はイベント一覧の `/events` 配下です。表示していない配置や行のひな型には実画面の座標を付けず、別ページへ移った場合はイベント一覧を非表示として報告します。会場編集やダイアログの独自描画部品は自動登録されないため、今後の接続対象です。

ライブラリーが通常の子ウィンドウ終了でもパイプ切断を報告する場合があったため、本体では診断をログへ記録し、閉じるたびにエラーダイアログを出さない扱いにしました。文房具 UI のドキュメント末尾には一部文字化けがあり、該当する設定の説明はソースで補って確認しました。[接続方法と調査結果](../../StyleSettings/developer-window.md) に記録しています。

ジャンルコード表とブロックの色網掛け対応表を、共通の「網掛け対応表」として扱うようにしました。表名、表のコメント、行の並び順、並び順のコメント、各行の名前・太線色・細線色・網掛け・コメントを、同じ編集処理で扱います。保存形式も共通化し、従来のデータを読み込めるようにしています。

スプリットペーンでは、左側のイベントと右側のパッケージを同じ操作で編集できます。行の新規作成・削除に加え、Shiftで範囲選択、Ctrlで行の追加・解除、Ctrl+Shiftで別範囲の追加に対応しました。複数選択した行は反対側へのコピーと削除を一括で行えます。複数選択中は反対側をグレーアウトし、コピーをキャンセルしたときは今回の一括操作全体を取り消します。コピー先の行へ操作対象を移し、画面内に見えるようにしました。

## 9月19日：ジャンルコード表の知見を交換できる v1.12.1

ジャンルコード表の読込みを、必要な項目を選んで交換できる比較画面へ変更しました。左に現在のイベント、右に読み込んだパッケージを置き、ジャンルコードを一意のIDとして文字コード順に整列します。同じコードは左右の同じ行に並び、色・網掛け・コメントの違いを確認できます。

左右それぞれへのコピー挿入・上書き・削除・コードのリネームと、元に戻す・やり直すを用意しました。イベントへの反映とパッケージへの保存は独立しており、必要な知見だけを受け取ったり、パッケージ側へ持ち寄ったりできます。サークルデータのジャンルは変更しません。保存失敗時は下書きを残し、別の操作で更新された元パッケージへの上書きを防ぎます。詳しくは [ジャンルコード表の比較・交換](../../../User/GetStarted/GenreCodeTableDiff.md) を参照してください。

ジャンルコード表には名前を付けられ、初期値は「イベントプロジェクト名_ジャンルコード表」です。配置案を選ばずに表単独をパッケージへ書き出し、今年のサークルデータにないジャンルも保持できます。オンラインミーティングで画面を共有しながら、ZIPなどで渡したパッケージから知見を交換する共同作業を想定しています。通信機能をアプリに持たせずに、蓄積した対応表を育てられるようにしました。

アプリケーション設定と共通スペース定義の保存先をOS所定のユーザーフォルダーへ移しました。Windowsでは `%LOCALAPPDATA%\CircleSpaceCoordinator` を使用し、ビルドの `bin`・`obj` 削除や配布ZIPの展開先変更で設定を失わないようにしました。移行先に設定がない場合は起動したEXEの隣の旧設定を引き継ぎ、新規設定でも既定フォルダーのイベントを検出します。macOS・Linuxのパス解決にも対応していますが、今回の配布とGUI確認はWindows版です。

画面右上の作業者欄は文房具UIの下線付き入力へ変更し、ポップアップを開かず直接編集できます。Editバッジはマウスを合わせたときだけ表示します。

## 9月12日：チャンネルで席の条件とサークルの列値を結び、v1.0.2 へ

［机配置］と［サークル配置］にチャンネルリストを追加しました。例えば［書籍］チャンネルを作り、明るい席に重み 1、低照度の席に 0 を設定し、Excel の［書籍の有無］列を対応させる使い方ができます。

### 席の条件を数値で入力する

［机配置］の右側リストからチャンネルを追加・編集・削除し、机上セルに 0～1 の実数を入力できます。Ctrl＋ドラッグによる範囲選択と一括入力にも対応しました。重みは色と数値で表示し、会場の座標に保存して机配置間で共有します。既存のブロック名・机番地・セル番地は、採点しない特別な［番地］チャンネルとして扱います。

［列・名前］から Excel / CSV の列を対応付けると、各サークルの列値と採点位置の重みを掛け合わせ、全サークルの合計をチャンネルの部分点にします。新規チャンネルは倍率 1、加算値 0 で、番地以外の部分点を合計します。複数セルのサークルは採点位置で一度だけ加点します。既存の評価項目の倍率や合体制約は維持しています。

列の空欄は 0 とし、不正な数値や対応列の欠落はエラーにします。Excel の表示が丸められていたりパーセント形式だったりしても、評価用には元の数値を保持します。定義・列対応・重み・取込み値は JSON 保存と Undo/Redo に対応しました。古い取込みデータで列が出ない場合は元の表を再取込みします。

### サークル側の値を画面で確かめる

［サークル配置］でも配置リストの下に［チャンネル］を置き、サークル名・サークルID・内部ID（従来の石番号）・各数値チャンネルを切り替えられるようにしました。［書籍］ならサークル側の 0、1 などが表示されます。従来の［ID］ボタンの役割をこのリストに移し、ID の正規表現・置換文字列の設定はリスト上部から開けます。選択と正規表現は次回起動時にも復元します。

開発者から、セルの重みを設定できることと、重みの係数とサークルの列値の掛け算が動作しているとの報告がありました。自動テストに加え、架空データでリスト表示、チャンネル切替、重み入力による部分点更新、正規表現の設定画面を確認しました。

## 9月6日：会場編集・Excel 出力・自動配置を拡充

日中は、会場の形状や席の管理を画面上で扱いやすくする改善を進めました。

### 会場と席の編集

島の接続をセル単位で表示し、自動接続を個別に無効化できるようにしました。柱や空きセルも扱い、物理的には接していても別の島として評価する配置を表現できます。

Ctrl を使った範囲選択と配置の交換、ブロック名・席名の一括入力、配置案間で机配置をコピーする機能を追加しました。重複した席名は赤く表示し、入力作業を続けながら修正箇所を確認できます。ウィンドウのリサイズや、会場全体を画面に収める操作も整えました。

### Excel への書き出し

サークル ID を照合し、選択した Excel の列へブロック名・席名を書き出せるようにしました。2スペースのサークルには机番号を出力し、必要な机番号が未入力の場合は画面で警告します。

読込み・保存中には進捗表示を出して二重実行を防ぎ、読込元と書出し先のフォルダーを別々に記憶するようにしました。

独立した最適化エンジンを追加しました。机の位置を固定したまま、サークルの配置を交換して改善案を探します。一般参加者向けの評価を優先し、同点ならサークル参加者向けの評価を比較します。

実行時間は 1～120 分で指定でき、途中で停止しても、それまでに見つかった最高案を返します。改善した場合だけ、元の案を残して新しい配置案を追加します。2スペースや合体サークルのまとまりを保つ処理も実装しました。

会場編集・席名入力・範囲交換・Excel 書出し・リサイズは実機で確認しました。この段階では、最適化を含む Application のテスト 39 件が成功しています。

## 9月1日：C# 版の基礎と Excel 連携を整備

配置のルールと評価計算を C# へ移し、会場、机、参加者、複数の配置案を JSON で保存・交換する基礎を実装しました。画面や Excel のセル番地に依存しない整数座標を使い、机の回転、重複、配置禁止セル、必要スペース数などを検証します。
