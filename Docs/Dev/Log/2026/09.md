# 開発日誌：2026年9月

Excel を中心とした配置作業を、画面上で編集・比較できる Windows アプリへ移す開発を進めています。今月は会場編集と Excel 入出力を整え、GitHub での配布を開始しました。画面共有中も操作を追いやすくするため、アプリ画面内に表示する「文房具 UI」への移行にも取り組んでいます。

新しい記録から順に掲載しています。記述は各日付時点の状況です。

## 9月12日：チャンネルで席の条件とサークルの列値を結び、v1.0.2 へ

［机配置］と［サークル配置］にチャンネルリストを追加しました。例えば［書籍］チャンネルを作り、明るい席に重み 1、低照度の席に 0 を設定し、Excel の［書籍の有無］列を対応させる使い方ができます。

### 席の条件を数値で入力する

［机配置］の右側リストからチャンネルを追加・編集・削除し、机上セルに 0～1 の実数を入力できます。Ctrl＋ドラッグによる範囲選択と一括入力にも対応しました。重みは色と数値で表示し、会場の座標に保存して机配置間で共有します。既存のブロック名・机番地・セル番地は、採点しない特別な［番地］チャンネルとして扱います。

［列・名前］から Excel / CSV の列を対応付けると、各サークルの列値と採点位置の重みを掛け合わせ、全サークルの合計をチャンネルの部分点にします。新規チャンネルは倍率 1、加算値 0 で、番地以外の部分点を合計します。複数セルのサークルは採点位置で一度だけ加点します。既存の評価項目の倍率や合体制約は維持しています。

列の空欄は 0 とし、不正な数値や対応列の欠落はエラーにします。Excel の表示が丸められていたりパーセント形式だったりしても、評価用には元の数値を保持します。定義・列対応・重み・取込み値は JSON 保存と Undo/Redo に対応しました。古い取込みデータで列が出ない場合は元の表を再取込みします。

### サークル側の値を画面で確かめる

［サークル配置］でも配置リストの下に［チャンネル］を置き、サークル名・サークルID・内部ID（従来の石番号）・各数値チャンネルを切り替えられるようにしました。［書籍］ならサークル側の 0、1 などが表示されます。従来の［ID］ボタンの役割をこのリストに移し、ID の正規表現・置換文字列の設定はリスト上部から開けます。選択と正規表現は次回起動時にも復元します。

開発者から、セルの重みを設定できることと、重みの係数とサークルの列値の掛け算が動作しているとの報告がありました。自動テストに加え、架空データでリスト表示、チャンネル切替、重み入力による部分点更新、正規表現の設定画面を確認しました。

### 外部 DLL に自己署名を付けない

9月11日の起動調査では、自己署名された `MonoGame.Framework.dll` が Windows のアプリ制御に拒否されていました。署名対象をこのリポジトリで作る EXE/DLL の許可リストに限定し、外部 DLL を元のパッケージの状態へ戻して再ビルドした後、開発者から起動成功の報告がありました。

今後も、他人が作った DLL・EXE には自己署名を追加せず、提供元の署名・未署名状態を維持します。今回の成功だけで全環境の実行許可を保証するものではありません。[署名方針](../../配布/コード署名.md#署名対象の方針) と [調査記録](../../Troubleshooting/Smart%20App%20Controlによる起動ブロック.md) に残しました。

### v1.0.2 の配布

共通バージョンを `1.0.2` に更新しました。[リリースページ](https://github.com/muzudho/CircleSpaceCoordinator/releases/tag/v1.0.2) で、必要な DLL・.NET ランタイム・編集／思考エンジンを含む Windows x64 用 ZIP を配布します。公開用 ZIP は前回と同様に追加署名せず、外部ファイルの状態を維持します。ソースのタグと配布物のバージョンを揃え、配布内容の検査と展開後の起動確認を行います。

## 9月9日：GUI の gRPC 接続への移行と配布の整備

エディター GUI → エディターエンジン → スペース配置の思考エンジンの経路を実装しました。GUI の机・参加者・配置案の編集は操作契約を送り、エディターエンジンが正本・選択・Undo/Redo を管理します。描画には評価・トポロジーを含む応答をキャッシュして使います。

編集・計算の実装を GUI から外し、共通の配置交換処理を Calculations に移しました。思考エンジンもエディター実装を参照しません。両方の依存方向をビルド時に検査します。ファイル入出力アダプターは TableIO として独立させました。

探索のジョブ ID・進捗ストリーム・停止 API を追加し、GUI の「ストップで途中の最高案を採用する」動作を保ちました。探索中の編集との版競合を検査し、計算を同時に１件へ制限します。指定した保存先にはセッションと履歴を操作ごとに保存し、再起動後に復元できます。保存に失敗した操作はメモリー上でも確定しません。

GUI のエンジン自動起動・終了、API 互換性の基準、CLI の操作・ジョブコマンド、ビルド・publish 時の同梱を追加しました。公開用のファイル検査はエンジンの必須ファイルを確認し、エンジン配下の設定・セッションデータも拒否します。gRPC 専用サーバーには不要な静的アセット・IIS 用設定を生成しません。

Release ビルドは警告・エラー 0 件。６つの C# テストプロジェクトが成功し、配布検査のテストは 10/10 成功しました。実通信では GUI のコントローラー、未使用の机配置、別の案への編集・コピー、停止した探索の結果、競合、再起動後の Undo、保存失敗時の状態保全を検証しました。Windows x64 のランタイム同梱出力を作成し、エンジンの自動起動・接続・編集・終了と、架空データによる GUI の起動・正常終了を確認しました。

途中の出力では Windows のアプリ実行制御による `0x800711C7` が発生したため、起動失敗時に子エンジンのログを示すようにしました。その後の最終出力の検証は成功しています。実行制御の設定や証明書ストアは変更していません。

[現在の構成・操作契約・起動・復旧・配布手順](../../設計/ヘッドレスエンジンとgRPC.md)

## 9月9日：ヘッドレスのエディターエンジンと思考エンジンを実装開始

エディター GUI、エディターエンジン、スペース配置の思考エンジンを分離し、gRPC で一方向に呼び出す方針を決めました。エディターエンジンは GUI なしで実行する独立したコンソールプログラムです。[設計と起動手順](../../設計/ヘッドレスエンジンとgRPC.md) にまとめました。

共有 `.proto`、編集サーバー、探索サーバー、gRPC 用 CLI を追加しました。CLI からプロジェクトの読込み・案名変更・Undo/Redo・書出しができ、エディターから別の思考サービスに依頼して探索結果を新しい案として追加できます。版チェックにより、探索中に行った編集を古い結果で上書きしません。

Release ビルドは警告・エラー 0 件。既存の５つの C# テストプロジェクトと、新しい実通信テストが成功しました。実通信テストでは編集履歴、版競合、セッション分離、探索と Undo、接続失敗時の状態保全、計算中の編集、キャンセル伝播を検証しています。２つのエンジンを別プロセスで起動し、CLI で読込みから探索・書出し・Close まで実行できることと、既存の出力ファイルを上書きしないことも確認しました。

初版時点では、既存 GUI の接続切替、残りの編集 API、進捗通知、セッション永続化、エンジンの配布・起動管理を次の段階としていました。その後の実装は上の同日記録を参照してください。

## 9月6日：v1.0.1 を公開。画面共有しやすい UI へ

同日公開した v1.0.0 に続き、[v1.0.1](https://github.com/muzudho/CircleSpaceCoordinator/releases/tag/v1.0.1) を公開しました。必要な DLL と .NET ランタイムを含む Windows x64 用 ZIP を配布しています。

### ダイアログをアプリ画面内へ

オンライン会議でアプリのウィンドウを共有すると、別ウィンドウのダイアログが参加者に見えない場合があります。そこで、確認や入力を同じ画面内で行えるようにする作業を進めました。

- 既存の机・手・カメラなどのアイコンを維持し、ボタン描画を文房具 UI の共通部品へ移しました。
- 配置の削除確認と、自動最適化の時間指定・進捗・停止・結果通知をアプリ画面内へ移しました。
- 既存配置の名前変更に、下線のある部分を編集する入力欄を試験導入しました。
- 名前変更ダイアログの本文には作業の説明を置き、キーボードの操作説明は画面下の専用帯へ分けました。

試用中に見つかった、文字とキャレットの位置ずれ、モーダル中に Ctrl+P で撮影できない問題、背後の机がホバーに反応する問題も修正しました。入力欄の外をクリックすると、ダイアログを開いたまま入力フォーカスを外せます。

利用者から、ボタン表示、下線入力、キャレット位置、操作説明の帯、背後の机がホバーに反応しないことについて、実機での確認報告を得ました。

### Windows 固有の処理を分離

Windows 用の実行プロジェクトを `CircleSpaceCoordinator.Desktop.Windows` に改名し、OS に依存しない操作・保存・ログなどを `CircleSpaceCoordinator.Desktop.Core` へ分離しました。文字編集の状態と、Windows の IME・クリップボード接続も分けています。

ファイル選択ダイアログは Windows の機能を利用する方針です。文房具 UI の独立リポジトリー化は、囲碁アプリと本アプリの両方で共通 API を検証してから進める案としています。アプリ全体の他 OS 対応はまだ完了していません。

### 配布と確認

v1.0.1 の実行ファイル名は `CircleSpaceCoordinator.Desktop.Windows.exe` です。v1.0.0 から名前が変わったため、リリースページにダウンロードする ZIP と起動する EXE を明記しました。

Release ビルドは警告・エラー 0 件。C# テスト 137 件と配布チェック 7 件が成功しました。配布 ZIP の全 317 ファイルについて展開前後のハッシュ一致を確認し、展開したアプリのイベント選択画面と架空サンプルの起動・終了も確認しました。

提供元の既存署名を保持し、新たなコード署名は追加していません。ZIP の起動成功報告はありますが、Smart App Control による許可は利用環境によって異なります。[配布に関する知見](../../配布/README.md) に調査と方針をまとめています。

### 次に進めること

IME の詳しい動作を実機で確認し、配置の作成・複製時の名前、机番号、席名などへ下線入力を広げます。一覧・表編集などには Windows フォームが残っています。完了した部分と残作業は [文房具 UI の移行進捗](../../開発/文房具UI/移行進捗.md) で管理しています。

## 9月6日：会場編集・Excel 出力・自動配置を拡充

日中は、会場の形状や席の管理を画面上で扱いやすくする改善を進めました。

### 会場と席の編集

島の接続をセル単位で表示し、自動接続を個別に無効化できるようにしました。柱や空きセルも扱い、物理的には接していても別の島として評価する配置を表現できます。

Ctrl を使った範囲選択と配置の交換、ブロック名・席名の一括入力、配置案間で机配置をコピーする機能を追加しました。重複した席名は赤く表示し、入力作業を続けながら修正箇所を確認できます。ウィンドウのリサイズや、会場全体を画面に収める操作も整えました。

### Excel への書き出し

サークル ID を照合し、選択した Excel の列へブロック名・席名を書き出せるようにしました。2スペースのサークルには机番号を出力し、必要な机番号が未入力の場合は画面で警告します。

読込み・保存中には進捗表示を出して二重実行を防ぎ、読込元と書出し先のフォルダーを別々に記憶するようにしました。

### 自動最適化

独立した最適化エンジンを追加しました。机の位置を固定したまま、サークルの配置を交換して改善案を探します。一般参加者向けの評価を優先し、同点ならサークル参加者向けの評価を比較します。

実行時間は 1～120 分で指定でき、途中で停止しても、それまでに見つかった最高案を返します。改善した場合だけ、元の案を残して新しい配置案を追加します。2スペースや合体サークルのまとまりを保つ処理も実装しました。

会場編集・席名入力・範囲交換・Excel 書出し・リサイズは実機で確認しました。この段階では、最適化を含む Application のテスト 39 件が成功しています。

## 9月5日：イベントの管理とサークル配置を実装

起動時にイベントを選択する画面を追加し、新規作成、既存 JSON の登録、複製、並べ替え、一覧からの除外を行えるようにしました。日本語イベント名のタイトル表示も修正しました。

机配置とサークル配置のモードを分け、机の向きを示す表示や、追加位置のプレビューを整えました。参加者一覧は C# から Excel・CSV を読み込み、シートと列の対応を確認して取り込めます。

サークルは画面上の駒として配置・移動・交換でき、2スペースや合体サークルも表示します。ズームと移動の状態をイベントごとに保存し、開き直したときに復元するようにしました。

アプリのアイコンとローカル署名・配布手順を整備し、Release ビルドと当時の C# テスト 76 件が成功しました。

## 9月1日：C# 版の基礎と Excel 連携を整備

配置のルールと評価計算を C# へ移し、会場、机、参加者、複数の配置案を JSON で保存・交換する基礎を実装しました。画面や Excel のセル番地に依存しない整数座標を使い、机の回転、重複、配置禁止セル、必要スペース数などを検証します。

当時は Python の Excel 変換処理を介して、既存データの読込み、C# での評価、Excel への書戻しを行う構成でした。元ファイルを直接変更せず、VBA を保持して別名保存する処理を整えました。この記録は移行初期の構成であり、現在の利用手順ではありません。

検証では、元ファイルと VBA が変更されないこと、出力した評価値が C# の計算結果と一致することを確認しました。重みと属性の取込みを調整した後、旧 Python 版と C# 版の5項目の評価値が、浮動小数点の丸め誤差の範囲で一致しました。Excel 本体による数式の再計算・保存は、この時点では未確認でした。

この段階で、Core・Application・Infrastructure・StationeryUI などへ役割を分け、後の画面編集と評価機能につながる基礎を作りました。
