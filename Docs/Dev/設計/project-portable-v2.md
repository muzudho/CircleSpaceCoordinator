# ポータブル第２・第３段階の実装契約

更新日：2026-09-18。第１・第1.5段階は [v1契約](project-portable-v1.md)、進捗と手動確認の残件は [実装計画](../開発/プロジェクトのポータブル実装計画.md) を参照。

## 操作

用語は「イベントプロジェクト」と「パッケージ」に統一する。イベントプロジェクトは作業全体、パッケージは選択した配置案・素材・知見と必須依存の受渡し単位。新規保存の推奨ファイル名はそれぞれ `*.event-project-csc.json` と `*.package-csc.json`。パッケージ全体の表示名は［パッケージのタイトル］と呼び、保存時に指定するファイル名とは区別する。

従来のイベントJSON、`*.project-portable.json`、`*.frame-layout.json` は引き続き読める。既存ファイルは自動改名しない。JSON内部のkind・形式番号は変更せず、拡張子だけで種類を判定しない。イベント一覧はイベントプロジェクトを、パッケージ・ライブラリーは新旧のパッケージを扱う。

［部分書出し］には配置案・知見に加え、会場と現在の配置案のフレーム定義・申込定義が並ぶ。配置用定義が未設定なら共通カタログを参照する。種類で絞り込み、［表示分を選択］で選べる。非表示のチェックは維持し、選択数は全種類の合計を表示する。別案の定義を取り出す場合は、その案を配置ページで選んでから開く。

現在の案のフレーム、またはフレーム全体を含む矩形範囲を選択してから開くと、［現在の案は選択範囲のフレームだけを書き出す］を選べる。島・領域は必要なフレームの集合として選ぶ。配置案の説明は配置ページで編集し、書出し画面では表示のみ。ファイル全体のメモは引き続き１つ。

［部分読込み］では項目を選び、取込先の配置案と方法を指定する。

| 方法 | 対象と動作 |
| --- | --- |
| 新規追加 | 配置は新しい案、知見は未対応付けで追加。定義は指定した配置案へ追加。会場は採用可否を検査 |
| フレームを挿入 | 配置・部分配置のフレームを指定した案へ追加。既存フレームを維持 |
| 配置案を置換 | 明示した案の全体を置換。案のIDと並び位置を保持し、名前は一覧の入力値を使用 |
| 共通カタログへ登録 | 定義素材だけをイベント外の共通カタログに登録 |

移動量X/Yは配置・部分配置にのみ適用する。申込定義の読込み値が衝突する場合、一覧の名前欄で別の値を指定して再確認するか、その項目のチェックを外す。確認画面には対象・変更内容・会場の扱いとプレビューを表示する。配置の青は適用後、赤の輪郭は変更前。素材・知見はプルダウンで切り替える。ひな形だけの知見には会場図がない。

［部分書出し］の［知見・ライブラリー ▼］→［ファイルライブラリー］からローカルファイルを閲覧する。初期フォルダーはアプリ配置先の `portable-library`。自動作成・自動コピーはせず、フォルダーを選択して使う。直下の専用JSONをファイル名順で先頭200件まで読み、名前・ファイル全体のメモ・タグ・ファイル名を検索する。各ファイルに代表サムネイル、項目数、マル秘を表示。壊れたファイルはエラー行として残す。

［メモ・タグ編集］ではファイル名を変えず、パッケージの名前・メモ・タグを編集する。内容・マル秘は保持。旧１案形式のメタデータを編集した場合は、同じファイルに新しいポータブル形式で保存する。読込みは拡張子より内容で判定する。

## 形式と依存

素材または部分配置を含むファイルは `formatVersion: 2`。配置案・知見だけなら従来のv1を継続する。旧 `.frame-layout.json` も読み込める。v2非対応の旧アプリは形式番号で拒否し、未知の素材を黙って捨てない。

- `items[].kind: frame-fragment` はフレームの部分配置。データ構造は１案形式と共通。
- `materials` は `frame-definition`、`request-definition`、`venue` を保持。各素材のID・種類・名前・マル秘は必須。
- フレーム定義は１件のみ。申込定義は１件と、その参照先フレーム定義だけを同梱。参照先不足や余分な型を拒否する。
- 会場は寸法・障害物・ゾーン・名前のみ。参加者・元表・入力値・割当・仮置き・評価結果・表示状態・保存先パスは同梱しない。
- 配置・知見・素材を合計して1～100件、16 MiB以内。IDの重複、一覧と内容の不一致、不明な形式・種類は拒否する。
- スキーマは `schemas/project-portable-v2.schema.json` と `schemas/portable-material-v1.schema.json`。参照整合性・合計件数・マル秘継承・会場形状は実行時にも検査する。
- 架空サンプルは `examples/fictional-materials.project-portable.json` と `examples/fictional-fragment.project-portable.json`。

## 定義と会場の取込み

同じID・同じ内容の定義は再利用する。同じIDで内容が異なる型は新IDを割り当て、申込定義や挿入フレームからの参照も付け替える。同じ申込読込み値で意味・参照先が異なる場合は拒否し、読込み値の変更または見送りを求める。既存定義を上書きしない。

配置用定義がない取込先には、確認に用いた共通カタログのスナップショットを土台として採用する。配置用定義への追加はイベントの編集履歴に含める。共通カタログ登録とイベント内取込みは別操作とし、片方だけ成功する複合操作を作らない。

共通カタログは候補全体の検証後に一時ファイル・置換で保存する。保存前の内容と適用後の内容を起動中だけ保持し、ライブラリーの［共通登録を戻す］で直前登録を取り消す。その後の別編集・外部変更があれば古い内容を上書きせず拒否する。取消しはイベントのUndoとは別で、再起動後や複数登録を遡る履歴・Redoは持たない。

マル秘はパッケージ・素材・元イベント・配置案・定義から継承し、取込先の既存マル秘も解除しない。共通カタログにマル秘を保存する場合はカタログの `schemaVersion: 2` とする。旧アプリが秘密指定だけを無視して再書出しすることを防ぐ。

会場単独の採用は、既存配置がある場合に形状が一致していることを要求する。配置がない場合は採用可能。配置・評価・参照の整合性は候補全体で検証し、失敗時は無変更。挿入・置換では常に取込先の会場形状との一致を要求する。

## 部分配置・差分採用の範囲

切出しは元会場の絶対座標を保持し、挿入時に整数X/Yを加える。フレームの向き・番号・席ラベル・選択フレームの島開始位置を保持する。島接続は両端が選択されている場合だけ、無効接続は両セルが選択されている場合だけ含める。向かい合わせ領域は矩形が選択セルの外接矩形に収まり、領域に触れる未選択フレームがない場合だけ含める。境界をまたぐ接続を切り詰めて作り直すことはしない。

部分配置には選択フレームで使う型・フレーム定義を同梱し、申込定義は含めない。必要なら別の申込定義素材として選ぶ。挿入時はフレーム・接続・領域のIDを割り当て直し、参照を維持する。番号は自動採番せず保持するため、既存案と番号が重なる場合は配置ページで編集する。境界で隣接したフレームは既存のトポロジー規則により自動接続される場合がある。

挿入による重なり・会場外・障害物との衝突を拒否する。置換は案全体に対する操作で、サークル配置が１つでもその案を参照している場合は拒否する。参照先を壊して割当を捨てる操作はしない。同じ取込先への置換と別の挿入・定義追加・置換を同時に選んだ場合も拒否する。１件ずつ確定するか、新しい案として追加する。

同名・出所IDに基づく自動対応、既存フレーム１件ごとの削除・更新、回転変換、異なる会場への座標変換は今回の範囲に含めない。これは原計画の「差分採用」の具体化であり、今回の機能で万能なマージを提供するものではない。

第1.5段階以外の評価設定を調査した結果、現行の `EvaluationConfiguration` はFeaturesとWeightMapsのみであり、新たに独立同梱する設定はない。固定の評価アルゴリズムや計算結果をファイルへコピーしない。知見は既存の列対応付けを経て取込先で再計算する。

## 適用・失敗・確認

読込みとプレビューは同じ固定した入力を使う。全項目の候補を作って検証し、イベントのrevisionを照合して１操作として適用する。Undo/Redoも１操作。１件の失敗で一部だけ追加しない。書出しは元イベントを変更しない。

ライブラリーのメタデータ保存は読込み時のファイル内容との一致を検査し、ロックと一時ファイル経由で保存する。古い画面から別プロセスの変更を上書きしない。手動のIME・DPI・画面操作検証は実装計画に未確認として残す。
