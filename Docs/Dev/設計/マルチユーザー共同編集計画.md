# マルチユーザー共同編集計画

更新日：2026-09-19

文房具 UI の下線テキストと `(change)` バッジを使う共通部品の設計案は、[変更タグエディター](../開発/文房具UI/変更タグエディター.md) を参照。変更タグ表示・１行入力・［閉じる］の有効条件をまとめ、他のアプリでも共通の操作感覚で使える構成にする。

## 目的と実装状況

パッケージを複数の人で受け渡す際に、各項目について「誰が、いつ、何を変更したか」を確認できるようにする。変更した編集画面を抜ける際に［１行チェンジログ］を必須入力とし、作業者・作業日と一緒に記録する。

本書は段階的に実装している計画である。共通の変更タグコンポーネントを作り、ジャンルコードの網掛け・ブロック色の編集に、１行チェンジログと［閉じる］の入力検証を導入した。Esc・Ctrl+S・通常のアプリ終了も同じ検証を通る。変更がない場合・全部元に戻した場合は入力不要。保存失敗時は適用した操作を Undo して入力を保持し、再試行できるようにした。

変更タグは既存の `PersonCredits` に `changeLog` を追加して保存する。作業者・作業日・チェンジログを編集内容と同じ Undo 単位で更新し、エクスポートによる提供者の更新では保持する。新しいチェンジログを持つタグは、変更者と変更日も必須とする。ログのない旧データは引き続き読める。

知見・会場・配置案・各定義など、他の編集画面への必須入力の展開と、未確定下書きの異常終了後の復元は残作業。今回の対応表編集は確定前の内容をメモリー内に保持する。共通部品の独立ライブラリーへの移設・パッケージ公開も今後の作業とする。以下の仕様には、この残作業の到達目標も含む。

既存機能は [知見の編集と作業者・提供者](知見の編集と作業者・提供者.md)、受渡し全体は [プロジェクトのポータブル計画](プロジェクトのポータブル計画.md) を参照する。

## 変更タグの定義

次の３つをまとめて［変更タグ］と呼ぶ。最新の変更１回分を、その変更対象に保持する。

| 項目 | 内容 |
| --- | --- |
| 変更者名 | 画面最上行の［作業者］。内部名称は Handle、最大16文字。アプリケーション設定に記憶する |
| 変更日時 | 画面最上行の右端に表示する［作業日］。`2026-09-19` の形式で記録する |
| １行チェンジログ | 何を変更したかを説明する１行の文章。最大1000文字 |

［変更日時］という名称でも、この計画で記録・表示する精度は日付までとする。画面に表示した作業日を記録に使い、別の時刻から日付を取り直して表示と食い違わせない。日付が変わる場合も、確定時の表示と記録を一致させる。

同じ作業者が再度変更した場合、変更者名は同じまま、作業日とチェンジログを今回の内容に更新する。変更していない項目の変更タグは更新しない。

## 変更タグを付ける単位

［パッケージの項目］とは、インポート・エクスポート時に選択チェックボックスが付く単位である。変更タグは、この単位ごとに付ける。ファイル全体に１つだけ付けるものではない。

| 現在の選択単位 | 変更タグの対象 |
| --- | --- |
| フレーム配置案 | 選択した配置案 |
| 部分配置 | 選択範囲から書き出す部分配置。抽出するだけでは新しい変更とせず、元の配置案のタグを引き継ぐ |
| チャンネルの知見 | 選択した知見 |
| 会場 | 選択した会場 |
| フレーム定義 | 選択した定義 |
| 申込定義 | 選択した定義 |

配置案内のフレーム１個、対応表の１行、ファイル全体の名前・メモ・検索用タグを、選択単位と混同しない。依存する定義を同梱するだけで、その定義の変更タグを上書きしない。

ジャンルコードの網掛け対応表とブロック色対応表を、それぞれ独立したパッケージ選択項目として追加した。素材種類は `genre-styles` と `block-styles`。各対応表全体が１項目で、行ごとにタグを作らない。読込みでは既存の対応表全体とタグを置換することを確認画面に明示し、１回の Undo で戻せる。同じ種類を複数選択した場合は拒否する。配置案に付随する部分的な対応表も同時に読み込む場合、明示的に選んだ全体の対応表を最後に適用する。

新しい項目種類や `changeLog` を持つファイルは、これらのフィールドに対応したアプリで読み込む。古いアプリでの読込み互換性は保証しない。

## 画面を抜ける条件

［キャンセル］［保存］の代わりに、確定して画面を抜けるボタンを［閉じる］に統一する。変更がある場合は、有効な１行チェンジログを入力するまで、このボタンを `Enabled = false` にする。

| 編集状態 | チェンジログ | ［閉じる］ |
| --- | --- | --- |
| 変更なし | 未入力でもよい | 有効。変更タグを更新せず閉じる |
| 変更あり | 未入力・空白のみ | 無効 |
| 変更あり | 1000文字超、改行を含むなど不正 | 無効 |
| 変更あり | 有効な１行、1〜1000文字 | 作業者・作業日も有効なら有効。内容と変更タグを確定して閉じる |
| 変更後、すべて元に戻した | 未入力でもよい | 有効。変更タグを更新せず閉じる |

「変更あり」は編集開始時の内容と比較して判定する。クリックした事実やチェンジログの入力だけでは、変更した扱いにしない。新規項目の作成は変更に含める。

Esc、Ctrl+S、別画面への移動にも同じ検証を適用し、未入力のまま確定しない。ウィンドウを閉じる際に変更があり、有効な変更タグがない場合は「変更を破棄してアプリケーションを終了しますか」と［終了する］［キャンセル］を表示する。［終了する］ではページを開いたときの対応表のコピーへ戻して終了し、［キャンセル］では編集内容・入力済みログを維持する。確認中に再びウィンドウを閉じても、確認を飛ばして終了しない。色選択など、項目編集を確定しない補助画面から戻る操作には入力を要求しない。

バックアップはページ開始時に `StyleMappingDraft` が保持する対応表のメモリー内コピー。未確定の変更はプロジェクト本体へ書き込まないため、破棄では以前の変更タグもそのまま残る。ディスクへのバックアップファイル作成や異常終了後の下書き復元とは別の仕組み。

## １行チェンジログ入力欄

プレースホルダーは次の文字列とする。

```text
変更内容を１０００文字で入力してください
```

上限1000文字であり、1000文字ちょうどの入力を要求しない。補助表示として文字数カウンター（例：`24 / 1000`）を設ける。

文字数の実装方針は Handle と揃え、Unicode スカラー値で数える。UTF-8 のバイト数や UTF-16 のコード単位数を上限として使わない。補助平面の文字も１文字と数え、結合文字や複数の文字から成る絵文字は構成するスカラー値の数で数える。

入力前後の空白を除いた文章を検証・保存し、空白だけの入力を認めない。改行を含む貼り付けや上限超過は、理由を表示して修正を求め、黙って切り捨てない。プレースホルダー自体を入力値にしない。

前回のチェンジログは表示しない。今回の入力欄は空欄で開始し、前回の文が残っているだけで入力済みになることを防ぐ。プレースホルダーと同じ必須入力の案内を欄の下へ重ねて表示しない。

## 前回と今回の表示

変更がなければ `by 名前 since 日付` のみを表示する。変更がある場合は今回を先頭に、旧情報を括弧内に表示する。［変更前］［変更後］というラベルは付けず、その直下にログ入力欄と［閉じる］を置く。

変更なしの例：

```text
by 一郎 since 2026-09-18 ［閉じる］
```

変更ありの例：

```text
by 二郎 since 2026-09-19（旧： 一郎 since 2026-09-18）
評論ジャンルの色を青に変更した  (change) ［閉じる］
```

今回の表示は確定前の予定であり、入力している途中で前回の変更タグを上書きしない。前回の情報がない場合は、変更者不明・日付不明と表示する。ジャンル配置のツールヒントの `by 提供者 since 日付` も、従来どおり直近の内容変更者・変更日を参照する。

## オートセーブとの関係

入力を検証し、変更した項目の内容と３つの変更タグをまとめて確定して、オートセーブに渡す。保存に失敗したら画面を閉じず、編集内容と入力を保持して再試行できるようにする。内容だけ、またはタグの一部だけが確定済みとして残る状態を避ける。

編集中の自動保存が必要な画面では、未確定の変更と入力を下書きとして復元できるようにする。未入力の下書きを、確定済みのパッケージ項目として書き出さない。異常終了後の復元でも入力要求を維持する。

１画面で複数のパッケージ項目を編集する場合の実装案は、今回のチェンジログを実際に変更した項目へそれぞれ記録する方式とする。入力欄の近くに対象項目を表示し、説明が変更対象全体を含むよう案内する。変更していない項目には付けない。

Undo/Redo では内容と対応する変更タグを一緒に扱い、別の編集内容のタグが残らないようにする。

## パッケージでの引継ぎと互換性

- エクスポート・インポートで、各項目の変更タグ３つを保持する。
- 受渡し、ID の付け替え、衝突回避のための名前変更だけでは、内容の変更者を受取人や書出し担当者に置き換えない。
- 受け取った項目を編集して確定したときに、その項目のタグを現在の作業者・作業日・今回のチェンジログで更新する。
- 最初と直近の［提供者］は、受渡しの情報として変更タグと別に保持する。書出しだけで変更日やチェンジログを更新しない。
- 古いプロジェクト・パッケージのタグ欠落を許容する。既存の変更者・変更日は維持し、チェンジログを捏造しない。次の内容変更から３つを揃えて記録する。
- プロジェクト保存形式、パッケージ形式、JSON スキーマ、プレビュー表示をまとめて更新する。既存の変更者・変更日との二重管理を避ける。

保存するのは最新の変更タグであり、全変更履歴はアプリ内に蓄積しない。過去の差分や履歴が必要な場合は Git で管理する。この計画はパッケージ受渡しによる共同編集を対象とし、リアルタイム同期や同時編集の競合自動解決は別途検討する。

## 実装順序と受入確認

1. 変更タグの保存形式を定め、既存データの読込みとパッケージ往復を対応させる。
2. ジャンルコードの網掛け編集に入力欄・変更検出・終了時検証・前回と今回の表示を実装する。
3. 対応表のパッケージ選択項目化と、他の各項目編集画面への適用を進める。
4. オートセーブ、終了経路、Undo/Redo、インポート後の再編集を確認する。

受入確認では、少なくとも次を満たすことを確認する。

- 未変更なら空欄で閉じられ、変更タグが変わらない。
- 色や網掛けを１か所変更すると空欄・空白のみでは閉じられず、有効な入力で閉じられる。
- 全変更を元に戻すと入力必須が解除される。
- 日本語・補助平面文字を含む1000文字は有効で、1001文字と改行入りは無効になる。
- 同じ人が変更しても、変更内容と作業日の更新が記録される。
- Esc・画面移動で未入力のまま確定できない。ウィンドウ終了時は明示的な破棄確認を通す。保存失敗でも入力が失われない。
- パッケージ内の変更した項目だけにタグが付き、往復後も３つが保持される。
- チェンジログがない旧データを開けて、次の編集時に入力を要求する。
