# サークルデータモード：計画と実装

## 目的と名称

読み込んだ Excel / CSV の値を、取込みダイアログを開き直さず確認できるようにする。ユーザーとの相談に基づき、書式・罫線・結合セル・画像は再現せず、値を閲覧する。

上部の左端の［サークルデータ］では入力データの閲覧と［Excel / CSV 読込］を行う。１段目の右端に［スペース番号書き出し］を置き、配置決定案の選択と書出し操作をこのページへ移す（2026年9月15日更新）。

## サークル配置決定と出力先

- ［確定する配置案を選択］で決定案を選び、［出力先］で［新しいファイルに書き出す］または［既存のファイルに書き出す］を選ぶ。
- 新規書出しは読み込み済みのサークル表を基に、出力ブロック番号・出力セル番の列を末尾に追加する。入力列を保持し、必要なら照合用サークルID列も追加する。新しい Excel（xlsx）または UTF-8 BOM 付き CSV を作成し、同名の既存ファイルは上書きしない。入力元のブックの書式・他シートは複製せず、取込み済みの値を出力する。
- 既存書出しは Excel（xlsx / xlsm）のシート、または CSV と UTF-8 / Shift-JIS を選択する。サークルIDで照合して、指定した番号列を更新する。
- 配置案の選択画面は左に配置図プレビュー、右に案名・一般参加者評価値・サークル評価値の一覧を表示する。一般参加者評価値の降順、同点ならサークル評価値の降順とする。作業中のフレーム配置にかかわらず全案を候補にする。
- 一覧の選択はプレビューだけを切り替える。［この案に確定］で決定し、キャンセルでは決定案・作業中の案を変更しない。現在の決定案には［確定中］を表示する。末尾の［配置案を未決定に戻す］では決定を解除できる。
- 各行の［ピン］、または P キーで選択中の案のピンを切り替える。［ピンのみ］、または F キーで絞り込み、評価順は維持する。ピンは案のIDで管理し、イベントごとの作業状態としてアプリ設定へ保存する。絞り込みの初期状態は全案表示。ピン操作は配置の確定とは独立する。
- 配置図は会場枠・障害物・フレームと配置済みサークルを全体表示し、サークルはジャンル色、仮置きはオレンジで描く。配置済み・仮置き・未配置の件数も表示する。
- ［出力列］でブロック番号・セル番の書込先と照合ID列を設定し、プレビューへ反映する。設定が完了し、決定案が書出し可能になるまで［書き出す］は無効。表の上に対応列と予定件数を明示し、書込先列の見出しを色分けする。
- 出力列の設定画面は左に列の一覧、右に３つの用途の割当先を表示する。左から右へドラッグして割り当て、右から外へドラッグするか［×］で解除する。同じ列を別用途へ移すと元の割当ては解除される。上下キーで列を選び、1 / 2 / 3 キーで割当て、Delete で選択した用途を解除する操作にも対応する。
- ［＋ 新規列［ブロック番号］を追加］［＋ 新規列［セル番号］を追加］で列を追加できる。同名列は番号付きの名前にする。設定中に追加して割り当てなかった列は適用時に除く。キャンセル時は元の表と列設定を維持する。既存ファイルにも末尾へ列を追加でき、Excel の既存の書式・別シートは維持する。
- このページの表は保存前の書出しプレビューを表示する。既存書出しでは入力元と同じファイルでも、別ファイルでも選択できる。出力先の選択やプレビューは取込みデータ・出力先ファイルを変更しない。
- 最後に［書き出す］で方法・ファイル名・出力列・件数を確認して保存する。保存後はファイルを読み直して表へ反映する。新規書出しの準備後に入力データを更新した場合は、出力先を選び直す。
- 出力先のパス・シート・列対応は現在のイベントを開いている間だけ保持する。イベントを開き直した場合は出力先を選び直す。外部で変更した表の再読込みも［出力先］から行う。
- CSV は選択した文字コードと UTF-8 の BOM の有無を維持する。引用符・セル内改行に対応し、文字コードで表現できない値や列指定エラーでは元ファイルを変更しない。CSV の引用符や空行などのテキスト上の書式は再生成する。

## 表示と保存

### スペース番号の規則

- １サークルが１フレームの配置可能セルをすべて占有するときは、セル数によらずフレーム番号を出力する。配置可能セルはサークルを置けるセル、配置不可セルは置けないセルを指し、配置不可セルはこの判定に含めない。配置可能セルが３つのフレームを３セルのサークルが占有する場合も対象。判定は実際の占有セル集合を使う。
- 全体占有でなく１セルだけ占有する場合は、そのセル番号を出力する。
- 全体占有でなく複数セルを占有する場合は未定義とし、`#UNDEFINED_SPACE_NUMBER` を出力する。３セルのフレームに２セル＋１セルで配置した場合、２セル側はこのエラー表記、１セル側はそのセル番号になる。
- セル番号を必要とする行で番号がない場合も `#UNDEFINED_SPACE_NUMBER`、ブロック番号がない場合は `#MISSING_BLOCK_NUMBER` とする。これらの行を黙って書出し対象から除外しない。プレビュー上にエラー番号の件数を表示する。
- 仮置きやフレーム番号自体の未設定は既存の検証どおり書出しを停止する。

### 表の閲覧・保存

- 上部に取込み元のファイル名・シート名・データ行数・列数を表示する。
- 行番号と列見出しを固定し、縦横スクロールバー、ホイール、Shift＋ホイール、矢印、PageUp/Down、Home/End に対応する。Ctrl＋Home/End は行・列の両方を先頭／末尾に移す。
- 表は閲覧専用。セルをクリックするとスクロール可能な全文の確認画面を開き、コピーできる。
- 成功した取込みのメタデータを `participantTableSource` に保存する。ファイル名は名前だけで、フルパスは保存しない。値は既存の `participants[].sourceValues` を参照し、大きな表の二重保存を避ける。
- 見出しと内部列キーを別々に保持し、空見出しや同名の列も元の列順で表示する。サークル順が取込み後のデータ行順となる。
- 表示値はアプリが取り込んだ値。Excel の数値は表示書式を付けない実数、文字列は既存の取込み規則に従う。先頭の使用行を見出しとし、完全な空行や前後の空白は既存の取込み処理で除かれる。行番号は取込み後の連番で、元シートの物理的な行番号ではない。
- JSON の再読込み、取込みの Undo/Redo に、値とメタデータをまとめて追従させる。元ファイルを変更しても再取込みするまでは表示は変わらない。
- 旧 JSON はそのまま読める。列値があれば保存済みの列値を表示し、列値がなければサークルID・名前等の基本情報を表示する。元の列順と出典を確実に復元するには再取込みする。
- 新しい `participantTableSource` を保存した JSON は、この項目を知らない旧アプリでは開けない。旧版へ戻す可能性がある場合は、更新前の JSON を保持する。
- 初期表示は［配置案　未決定］で、書出しを無効にする。［配置決定案を選択する］の一覧で決定すると、その案名を表示する。キャンセルでは変更せず、一覧の［配置案　未決定］で決定を解除できる。
- 決定案はプロジェクトの `exportPlanId` に保存する。作業中の案の選択とは独立し、JSON 復元・Undo/Redo に対応する。決定案の削除時は未決定へ戻り、削除の Undo では決定も戻る。旧 JSON では未決定で開始する。
- 書出しは決定案の席番地を出力先の Excel / CSV に反映する。案の内容を凍結する機能ではなく、書出し時点の最新の内容を使う。仮置き・机番号の既存検証を維持する。表内編集は対象外。

## 性能方針と検証目標

画面に入る行・列だけを参照して描画する。固定幅・固定高のセルを使い、全行を走査する自動列幅計算はしない。表の値を別の行列へコピーしない。表専用の文字テクスチャーは表示ページ単位で破棄し、長い値のプレビュー長も制限する。スクロールで GPU メモリーを無制限に増やさない。

取込みダイアログの先頭100行制限も外し、DataGridView の仮想モードで全行を参照できるようにする。

検証目標は 1万行 × 100列。ただし一律の動作保証や上限ではない。表の表示・取込み・gRPC の転送・JSON 保存は別々に測る必要がある。現状の Excel 読込みはブック全体をメモリーへ展開し、gRPC のメッセージ上限は 32 MiB。長い値が多い場合は同じ行列数でも転送上限やメモリー制約に先に達する。将来さらに大きな表を扱う際は、ページ取得 API・分割取込み・保存形式の見直しを検討する。

## 確認項目

- 取込み→列順・空見出し・重複見出し・実数値の表示→JSON 保存・再読込み。
- 取込み Undo/Redo で値と出典が一緒に戻る。キャンセル・失敗時は元データを維持する。
- 旧データ・0行・幅広の表・末尾行列・ウィンドウサイズ変更・長いセル値。
- 表のホイールやクリックが会場の移動・回転・配置変更を起こさない。
- 他のモードから読込ボタンが消え、既存の書出しと配置操作が使える。

## 実装後の検証（2026年9月12日）

配置決定案の選択機能追加後は Desktop テスト 48/48 が成功。未決定での拒否、作業中の案と異なる決定案からの席番地生成、JSON 復元、決定解除、削除と Undo/Redo を実通信で検証した。GUI でも初期の［配置案　未決定］・無効な［書き出す］、選択ダイアログ、決定後の案名表示・書出しボタンの有効化を確認した。

- Release ビルド・Windows x64 の publish が成功（ビルドの警告・エラー 0 件）。
- Desktop テスト 47/47、Infrastructure テスト 14/14 成功。取込み情報を実際の gRPC 経由で更新し、JSON 復元、Undo/Redo、出典のないデータへの再取込みを確認した。
- 1万行 × 100列のデータを作成し、末尾セル参照・スクロール範囲・表示モデルが表を複製しないことを検証した。一例ではモデル作成と 334 ページ分（各30行×10列）の値参照に 11 ms、同区間の追加割当て 176 bytes。元データの構築、GUI 描画、Excel 取込み、gRPC 転送、保存はこの測定に含まない。
- GUI では架空の200行 × 30列を使い、表表示、ウィンドウサイズ変更後の表示、縦横スクロールバーによる最終行・最終列の表示、サークル配置からの読込ボタン撤去を確認した。
- 途中で Windows のアプリ制御に自作 DLL の拒否が発生した。確認用出力では既存の開発用証明書と元のビルド出力を使って自作 DLL の署名状態を調整し、検証を完了した。外部 DLL の署名や OS の制御設定は変更していない。
