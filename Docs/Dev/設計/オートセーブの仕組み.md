# オートセーブの仕組み

更新日：2026-09-20

## 対象と目的

［ジャンル ＞ 色網掛け］の変更スコープでは、左側のプロジェクトと右側のパッケージを自動保存する。
保存と変更コメントの確定は別の状態として管理する。保存済みになっても、開始時点から変更が残っていれば、変更タグが画面の出口を抑える。

右側は［パッケージ読込］で選んだ `*.package-csc.json` の元のパスへ保存する。［読取］だけでは書き込まない。［反対側へコピー］で表が変わると保存対象になる。
選んだジャンルコード表以外のパッケージ項目・メタデータは保持する。

## 保存タイミングと表示

1. 表の内容、表名、並び順、コメント、または変更タグの有効な変更コメントが変わると、待ち時間を最初から数え直す。
2. 最後の変更から **1.5 秒**経過すると保存する。
3. モーダル表示中・IME変換中はこのページのタイマー保存を待つ。
4. 右下のバーは待ち時間に応じて伸び、満杯になると保存する。保存済みは満杯、失敗時は赤色の表示になる。
5. ［閉じる］などで画面を離れるときは、タイマーを待たず残りを保存する。

作業者が未設定なら変更内容の保存を止め、設定を促す。保存失敗時は入力・バックアップ・未保存状態を保持し、通常の画面に戻った後に1.5秒間隔で再試行する。［閉じる］でも再試行できる。
バーは書き込みバイト数を示すものではなく、保存を開始するまでの待ち時間を示す。書き込みは同期処理であり、大きなファイルではその間描画が止まる。

一般のプロジェクト自動保存は従来どおり `VenueEditorGame.AutoSave.cs` のリビジョン・表示位置監視で動く。このページではその前に下書きを反映する処理を追加した。ブロック番号等の共通色編集ページは従来の確定処理を使う。

## 保存済みと変更スコープを混同しない

| 状態 | 比較相手 | 用途 |
| --- | --- | --- |
| プロジェクトの変更あり | 編集開始時の下書き・表名・並び順・全体コメント | 左の破棄ボタン、変更タグ |
| パッケージの変更あり | 読み込み時のジャンルコード表 | 右の破棄ボタン、変更タグ |
| 保存待ち | 最後に保存成功した内容と変更コメント | タイマー、保存、保存エラー |

保存成功で更新するのは「最後に保存成功した内容」。編集開始時・読込時のスナップショットは更新しない。
変更タグと変更コメントは左右別に持つ。従来の変更タグは［プロジェクトへの変更コメント］、右側の表を読み込んだときに追加されるタグは［パッケージへの変更コメント］である。
右側の変更時は、タグの入力欄または［入力・編集］から専用の入力ダイアログを開く。入力確定後の文字列だけをパッケージの自動保存に使う。キャンセルした入力は反映しない。

変更タグはグリッドと同じ左右のペーンに横並びで配置する。左にプロジェクト用、右にパッケージ用を置き、各側の破棄・入力ボタンもそのペーンから位置を求める。［閉じる］は下段の共通操作領域に置く。
入力欄・変更バッジの描画とクリック判定は `ChangeTagEditorView.GetInputBounds` / `GetBadgeBounds` を共用する。固定座標や前フレームの描画結果を判定に流用しない。グリッドと変更タグの縦方向の縮尺はパッケージ読込で変更しない。

| プロジェクトの変更 | パッケージの変更 | 画面を離れるために必要なコメント |
| --- | --- | --- |
| なし | なし | 不要 |
| あり | なし | プロジェクトへの変更コメント |
| なし | あり | パッケージへの変更コメント |
| あり | あり | 両方の変更コメント |

片側のコメントを入力しても、もう片側の入力済み扱いにはしない。［閉じる］、Esc、Ctrl+S、アプリ終了、および確定を経由する画面遷移は、両方のタグの判定を通る。変更した側を破棄した場合は、その側の入力をリセットし、残った側のコメントは保持する。

その側の変更コメントが未入力・不正の場合、タイマー保存用には `編集中（変更コメント未確定）` を使う。これは最終的な変更コメントの代用ではない。IME変換中・モーダル入力中はタイマー保存を待つ。
有効なコメントを入力すると、内容が同じでも変更タグの保存をやり直す。画面を閉じる際は有効なコメントと保存成功の両方を確認する。
アプリの終了操作も同じ出口を通り、未確定コメントや保存失敗を飛び越えて終了しない。

## 左右別の破棄

- ［プロジェクトへの変更を破棄］：左側の下書き、表名、並び順、並び順コメント、全体コメントを開始時点に戻す。保存時の変更者・変更日・変更コメントも開始時点のものへ戻す。
- ［パッケージへの変更を破棄］：右側の表を読込時点へ戻す。保存時は保持した元のJSON文字列でファイルを復元する。
- もう片側に変更があれば画面に留まる。破棄した側の復元だけを自動保存する。
- 両方に変更がなくなったら、復元の保存が成功した後で画面を閉じる。保存失敗時は閉じない。
- 自動保存前に破棄して最後の保存状態へ戻った場合、不要な書き込みは行わない。

プロジェクトの下書きには、参加サークルのジャンルから補完された既定の色設定も含まれる。プロジェクト復元の基準はこの画面を開いた時点の下書きであり、イベントJSON全体のバイト単位の復元ではない。

## パッケージのバックアップと競合対策

`PackageGenreSaveSession` は次を保持する。

- 絶対保存パス
- 読込時のJSON文字列 `OpeningJson`
- 読込時の表 `OpeningTable`
- 最後に保存成功したJSON文字列 `CurrentJson`
- 最後に保存成功したパッケージ

通常の保存では既存の `UpdatePortableGenreTable` を使い、選択表を差し替えて変更タグを更新する。破棄では `OpeningJson` を保存する。
どちらも `PortableLibraryService.SaveMetadata` を通し、協調用ロックと元ファイル内容の一致確認を行う。外部でファイルが変更された場合は、復元も含めて上書きを拒否する。
保存成功後だけ `CurrentJson` を更新する。失敗時に新しい値へ進めない。
保存の実体は既存の `FrameLayoutPortableService.SaveDocument` を使う。イベントの保存先と同じパスへの書き込みは禁止する。

変更があるパッケージを別の表へ切り替える際は、有効な［パッケージへの変更コメント］と保存成功を必要とする。未確定なら、そのコメントを書くかパッケージ側の変更を破棄するよう案内する。プロジェクトの変更スコープは引き続き開いたままとする。

バックアップは**この画面のスコープ中のメモリー保持**。再起動後の破棄用スナップショットやパッケージの世代別バックアップは今回の実装にはない。異常終了した場合、最後に自動保存した内容と暫定コメントはファイルに残る。
プロジェクトの既存の保存ポイント・世代管理はそのまま使用する。

## 検証と引継ぎ時の確認

自動テストは [GenreAutoSaveChecks.cs](../../../tests/CircleSpaceCoordinator.Desktop.Tests/GenreAutoSaveChecks.cs)。パッケージ保存、コメント確定、元JSONへの復元、外部更新の拒否、プロジェクトのコメントだけの確定と元タグ復元を検証する。

実画面では次の順で確認する。

1. 右側へコピーし、バーが満杯になると元のパッケージが更新されること。
2. 保存済みでも、変更した側のコメントなしでは閉じられないこと。両側を変更した場合は、片側だけ入力した状態では閉じられず、両方入力したら閉じられること。
3. 両側へコピー後、一方を破棄しても画面が開いたままで、もう片方の破棄ボタンが残ること。
4. 両方を破棄すると、復元保存の成功後に閉じること。
5. 左右に異なるコメントを入力し、それぞれの保存先に対応するコメントが残ること。片側のコメントだけを書き直しても、もう片側のコメントを上書きしないこと。
6. パッケージを外部変更した場合、上書きも破棄復元も拒否され、画面に入力が残ること。

左右のファイル保存は独立しており、二つのファイルをまとめた原子的トランザクションではない。片側だけ成功しても、もう片側の失敗を保持して終了を止める。
今後、非同期保存へ変更する場合は、保存開始時のスナップショットと完了時点の比較を維持し、保存中の新しい編集を保存済み扱いにしないこと。
