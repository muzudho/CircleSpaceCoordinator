# プロジェクトの部分受渡し：実装契約 v1

2026-09-18。第０・第１・第1.5段階の実装記録。第２・第３段階は後続。Windows画面の実操作によるIME・表示倍率・スクロール確認は未実施。

## 操作

- ［フレーム配置］の［配置案の説明］で、選択した案の説明を改行付きで編集・保存する。空欄で消去でき、Undo/Redoの対象になる。説明は通常保存と部分受渡しで保持する。
- 書出し時に入力するメモは［ファイル全体のメモ］１つ。各配置案の説明は一覧の［説明（表示のみ）］に表示し、書出し画面では編集しない。
- ［フレーム配置］の［部分書出し］で配置案と保存済み知見を選び、名前・説明・タグ・マル秘を指定する。無選択では確定できない。内容確認後、`.project-portable.json` に保存する。元イベントと共通カタログには書込みを行わない。
- ［部分読込み］で新形式または従来の `.frame-layout.json` を開く。初期選択はなし。全選択・解除、追加名の編集、確認、適用の順で進む。同名は改名または選択解除で解消する。追加した内容は通常のイベント保存で残す。
- ［部分書出し］内の［知見の保存・列対応］で、現在の評価チャンネルから説明・狙い・推奨列名・値の意味・許可数値・空欄ルールを付けて知見を保存する。重み、既定値、係数は現在値を保持する。この操作自体はイベントの編集なのでUndo対象。
- 知見は未対応付けの再利用用スナップショットとしてイベント内に保存する。知見の一覧で閲覧できる。実際の列を明示選択して新しい評価チャンネルへ適用するまでは評価へ作用しない。適用後も元の知見を再配布用に残す。既存の同名チャンネルには上書きせず、別名を求める。
- 知見を書き出す際の［ひな形のみ］は座標別重み・会場を除き、説明・入力ルール・係数・既定重み・マル秘を保持する。

## 形式・依存とID

`kind: circle-space-project-portable`、`formatVersion: 1`。スキーマは `schemas/project-portable-v1.schema.json`。名前、説明、タグ、パッケージのマル秘、`items` を必須とする。知見がある場合は `knowledge` を追加する。配置と知見は合計1～100件、入力はUTF-8で16 MiB以下。未知のプロパティ・種類・版を読み捨てない。

`items` の各項目は `id`・`kind: frame-layout`・`name`・`data` を持つ。`data` は旧１案形式と同じ形の依存完結スナップショット。一覧のID・名前と実データが違えば拒否する。旧形式の入力は候補１件へ変換する。

| ID / データ | 有効範囲・受渡し時の扱い |
| --- | --- |
| 配置ID | イベント内。取込み時に新規IDを指定する。元IDは照合キーに使い、上書きキーにしない |
| 型ID | スナップショット内。複数案が元の同じ型を使っていても案ごとに同梱。取込み先で案ごとに新規割当てし、各フレームの型参照を置換する |
| 定義・申込定義ID | 各配置のカタログ内。同IDで異なる内容でも別案の定義を統合しない。申込定義は未使用分も全件保持し、その参照先と配置済み型の定義を含める |
| フレームID | 配置内。島の接続・起点・セルラベルからの参照と一緒に保持する |
| セル | 型内の相対座標または会場の絶対座標。挿入時の座標変換は行わない |
| 接続・向かい合わせ領域ID | 配置内。参照先フレーム・相対セル・座標とともに保持する |
| ブロック表示 | 選択案のセルラベルが参照する番号だけ同梱。同番号の表示が取込先と異なれば拒否する |
| 会場 | 選択案に必須。既存の未配置判定を共有して入力元の採用／既存の保持をプレビューし、形状相違は配置取込みを拒否する |
| 知見ID | イベント内の知見一覧。選択キーは `knowledge:` + ID。パッケージ内で配置項目のキーと衝突する場合も拒否する |

プレビューは件数・追加名・会場の扱いと、配置／知見IDの対応、型IDの対応表を返す。適用時にも同じ規則で再計算する。固定した入力と取込先revisionが一致しなければ適用しない。

フレーム出力は新しいプロジェクトから許可項目だけを組み立てる。参加者、元表、サークル配置、入力値、評価設定・結果、画面位置、出力先を含めない。歴史的な配置型とカタログの形状が矛盾する場合は黙って補正せず拒否する。

## 知見の所有・対応付け

`ChannelKnowledge` は通常イベントの `channelKnowledge` に保存し、`Evaluation` とは別に保持する。対応版以前の読込実装は未知項目として拒否するため、黙って消失しない。知見を持たない旧データではこのプロパティを省略する。

現行の重みはイベント共通のため、会場名・寸法・障害物・ゾーンと座標別重みをスナップショットにする。配置ごとの所有物とは扱わず、配置案そのものは知見の必須依存にしない。別会場の知見も未対応付けとして保存・閲覧できるが、評価への適用時には会場形状を照合する。会場の自動置換・座標変換はしない。

`Scale`・`Offset`・`OverallWeight`・既定重み・入力ルール・マル秘は必須。欠落した係数に既定値を補わない。説明としての値の意味と、実行時の許可数値一覧は別フィールド。許可数値なしなら任意の有限数を許可する。空欄を0にするかエラーにするかを選べる。列欠落と非数値はどちらもエラーであり、0にはしない。

適用は新規チャンネルの追加。サークル列の存在、全行の値、会場形状、同名・同IDを検査してからコミットする。追加チャンネルはイベント全体の評価へ作用することを確認画面に表示する。既存マップ・係数は更新しない。

## 一括適用・秘匿性・境界

エンジンの `Portable` RPC は抽出・解析・プレビュー専用。適用は `ImportPortableSelection` を既存のrevision付き `Execute` へ渡す。GUIは読込み済みデータを保持し、確認中にファイルを再読込みしない。全件を不変モデルの候補上で構築・検証してから１回コミットする。失敗・取消しで部分変更せず、Undo/Redo各１回で戻せる。

パッケージのマル秘は、元イベント・選択した配置／知見・書出し指定の論理和。部分取込みでも継承し、既存フラグを解除しない。知見のマル秘を通常保存・ひな形・再書出しでも維持する。マル秘は警告フラグであり暗号化ではない。

Applicationは抽出と適用、InfrastructureはJSON検証、Engine.Model/Contractsは転送型、EditorClientは通信、Desktopはファイル操作と選択画面を担当する。
