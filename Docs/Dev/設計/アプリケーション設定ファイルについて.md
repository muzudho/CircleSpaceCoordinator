# アプリケーション設定ファイルについて

2026年9月19日。v1.12.0 後の変更と引継ぎ事項。

## 方針と背景

ユーザーごとの設定は OS 所定のユーザー専用フォルダーへ保存する。EXE と同じフォルダー、`bin`、`obj` は保存先にしない。ビルド出力の削除、アプリの再ビルド、配布 ZIP の展開先変更によって、設定を失わないためである。

従来は EXE の隣の `application-settings.json` にイベントの登録一覧を保存していた。一方、`scripts/Build/Clear-BuildOutput.ps1` は各プロジェクトの `bin`・`obj` を削除し、ビルド・配布処理から呼び出される。そのため設定も削除対象になっていた。さらに、設定が存在しない起動では初期値を即座に返し、既存イベントを検索する処理に到達しない不具合があった。

調査時は Debug 版の設定が空で、そこに記録されたプロジェクト保存フォルダーにはイベント JSON が4件残っていた。登録一覧の消失と、イベント本体の消失は区別すること。

## 保存先

以下のフォルダー内に `application-settings.json` と `space-definitions.json` を保存する。

| OS | 保存フォルダー |
| --- | --- |
| Windows | `%LOCALAPPDATA%\CircleSpaceCoordinator` |
| macOS | `~/Library/Application Support/CircleSpaceCoordinator` |
| Linux | `$XDG_CONFIG_HOME/CircleSpaceCoordinator`。未設定・空・相対パスなら `~/.config/CircleSpaceCoordinator` |

Windows は .NET の `Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData)` で取得する。ユーザー名や `C:\Users` を固定しない。イベントへの絶対パスなど PC に依存する情報を含むため、ローミング用の `%APPDATA%` ではなくローカル領域を使う。

macOS は現在のユーザーホーム配下の Application Support を使用する実装である。将来サンドボックス配布へ対応する際は、OS の API が返すコンテナ内の保存先を使用するよう確認・調整すること。現時点で macOS・Linux の GUI 起動を保証する変更ではない。

バージョン番号、Debug/Release、EXE の展開先でフォルダーを分けない。同じ OS ユーザーの各起動先は同じ設定を利用する。複数プロセスによる設定の同時編集・統合には未対応なので、異なる起動先から同時に編集すると後の保存が優先される。

## 保存するもの

- `application-settings.json`：イベント登録一覧、プロジェクト保存先、最後のプロジェクト、表示・作業状態、入出力フォルダー、ハンドル、バックアップ設定など。
- `space-definitions.json`：ユーザー共通のフレーム・申込スペース定義カタログ。これもビルドで失わないよう移動する。

イベント本体はユーザーが指定した場所に保存する。既定の場所はドキュメント配下の `CircleSpaceCoordinator/Projects`。今回、イベント本体や既存のセーブポイント・ログ・素材ライブラリーの配置は移動していない。

## 旧設定の引継ぎ

1. 新しい保存フォルダーを作成する。
2. 対象ファイルが新しい保存先に存在すれば、それを優先する。
3. 存在しなければ、今回起動した EXE の隣にある同名ファイルをコピーする。
4. 旧ファイルは削除しない。コピーを一時ファイルへ完成させてから、新しい保存先へ上書きなしで移す。

2つの設定ファイルは個別に引き継ぐ。別の配布フォルダーや過去の `artifacts` は自動検索しない。旧設定がそこにしかない場合は、アプリ終了後にユーザーが必要な設定を選んで移す。新しい設定がある状態で別の EXE を起動しても、古い設定へ戻さない。

既に削除された登録一覧はコピーできない。新規設定でも既定のプロジェクトフォルダーを検索し、読込み可能なイベント JSON を一覧へ登録するよう修正した。既存設定の一覧が空の場合は、その設定の `projectsDirectory` を検索する従来の処理を継続する。検索は直下の `*.json` のみで、子フォルダーは再帰検索しない。別の場所のイベントは［既存ファイルを登録］で指定する。

## 実装と検証

- `CircleSpaceCoordinator.Desktop.Core/Persistence/UserSettingsPaths.cs`：OS ごとの保存先解決と旧ファイルのコピー。
- `ApplicationSettingsService.cs`：設定フォルダーの作成と、初回起動でも既存イベントを検索する処理。
- `VenueEditorGame.cs`、`VenueEditorGame.SpaceDefinitions.cs`：本番の読込み先をユーザー専用フォルダーへ変更。
- `tests/CircleSpaceCoordinator.Desktop.Tests/UserSettingsChecks.cs`：OS 別パス、XDG の既定値、初回検索、旧設定の保持、新設定優先、ビルド出力削除後の存続を検証。

テストは一時フォルダーを使い、実際のユーザー設定を変更しない。エディターエンジンへの接続後にイベント情報を読み込む順序は維持する。移行先の作成やコピーが失敗した場合は例外を通知し、EXE の隣へ保存先を戻さない。

検証結果：Windows アプリの Debug ビルドは警告・エラー0件。Desktop.Tests は通常の Windows ユーザー権限で99件すべて成功。制限環境では既存の Windows 暗号化テストが失敗するため、通常権限で再確認した。macOS・Linux はパス解決の単体検証のみで、各 OS での実行および今回の GUI 操作確認は未実施。

既存の設定サービスには、設定の読込み失敗を初期値へ戻して保存する処理が残っている。破損設定を上書きせず退避・通知する改善は今後の課題。通常保存の一部は書込み失敗時にメモリー上の設定を維持するため、保存失敗の利用者への通知も別途検討する。
