# イベントプロジェクト選択画面 実装計画

## 目的

アプリケーション起動時に作業対象のイベントプロジェクトを明示的に選択できるようにする。イベントごとの業務データと複数の配置案は一つのイベントプロジェクト JSON に保存し、アプリケーション設定にはローカルのイベントプロジェクト一覧と表示順を保存する。

## データの責務

### アプリケーション設定

`application-settings.json` はPC・利用者ごとに一つ置き、次を保存する。

- 設定ファイル仕様のバージョン番号 `schemaVersion`
- イベントプロジェクトの既定保存フォルダー
- 最後に開いたイベントプロジェクト
- 順序付きイベントプロジェクト一覧
- ファイルが見つからない場合にも表示する、最後に確認したイベント名

一覧から除外してもイベントプロジェクトファイルは削除しない。既存の `projectsDirectory` と `lastProjectPath` だけを持つ設定ファイルは自動的に読み込めるよう後方互換性を保つ。

現在の設定ファイル仕様は `schemaVersion: "1.0"` とする。バージョン項目のない旧設定は1.0として読み込み、次回保存時に番号を追加する。イベントプロジェクトJSON自身も、従来どおりトップレベルの `schemaVersion` で仕様を識別する。

`application-settings.json` は利用者が実行時に更新するファイルであり、ビルド・発行時に空の雛形を実行フォルダーへ再コピーしてはならない。登録一覧が空の場合は、設定されたプロジェクト保存フォルダー直下の有効なイベントプロジェクトJSONを検出し、一覧を自動復旧する。イベントプロジェクト本体の内容は変更しない。

### イベントプロジェクト

イベントプロジェクト JSON はイベントごとに一つ置き、イベント情報、会場、机、参加サークル、評価設定、複数の配置案を保存する。複製時は内容を引き継ぐが、イベントIDとイベント名を新しくする。

## 初期実装の操作

2026-09-04に以下の初期実装を完了した。

1. 起動時にイベントプロジェクト一覧を表示する。
2. 選択したファイルを「開く」またはダブルクリックで開く。
3. 「新規作成」で空のイベントプロジェクトを保存し、一覧へ追加する。
4. 「既存ファイルを登録」で既存JSONを検証し、一覧へ追加する。
5. 「複製」で選択したイベントを別ファイルへ保存し、一覧へ追加する。
6. 「上へ」「下へ」で表示順を変更する。
7. 「一覧から除外」で登録だけを消す。実ファイルは削除しない。
8. 見つからないファイルは警告表示し、勝手に一覧から削除しない。
9. コマンドライン引数でJSONを指定した場合は、従来どおり選択画面を省略して直接開く。

## 実装境界

- 一覧操作と設定保存は `Persistence` のGUI非依存サービスへ置く。
- 選択画面は起動前のWindows Formsダイアログとして `Desktop` に置く。
- 選択後は既存の `VenueEditorGame` を変更せず起動する。
- 実データやイベント名を操作ログへ書かない。

## テスト

- 旧形式設定の読込み
- 登録と重複登録の防止
- 表示順の上下移動
- 一覧から除外しても実ファイルが残ること
- 新規作成と複製で有効なJSONが生成されること
- 複製後のイベントIDが元と異なること
