# 申込スペース・スペース定義の引継ぎ

記録日: 2026-09-13。v1.2.0 公開後の相談をまとめた設計資料です。資料作成後に［スペース定義］モードと共通定義の編集・保存を実装しました。型を使った会場配置・申込データ読込み・割当てへの接続は未実装です。数字は半角で記載します。

## 目的

イベントによって、長机に配置するサークル数や、机を使わない場所・ブースの扱いが異なります。占有セル数だけで申込みと割当てを判断せず、アプリ全体で1つの型・申込区分の定義を持つ方針に変更しました。各イベント・机配置案・サークル配置案はこの共通定義を参照する設計です。

物理的に占有する範囲と、サークルに割り当てる区画を分離します。「席ではないセル」と「まだ割り当てていない席」も区別します。

## 利用者と確認した方向

- サークルの列名は［申込スペース］とする。
- 現在の入力値 `1` は「長さ2セルの長机のうち1セル」、`2` は「長さ2セルの長机のうち2セル」という定義として捉える。
- 利用者の追加指示により、定義はイベント別ではなくアプリ全体で1つとする。
- 机だけでなく、フリースペースやブースを定義・配置できるようにしたい。
- 島の接続は、すべてを自動判定する必要はない。セル単位の手動指定で扱える方針とする。
- 次の6例を具体的な設計対象とする。

| 配置物の型 | 占有範囲 | 割当区画 | 辺の条件 |
| --- | --- | --- | --- |
| 長さ2・2サークル用長机 | 2×1 | 1セルずつの2区画 | 正面・向きの扱いは従来を踏まえて設計 |
| 長さ2・1サークル用長机 | 2×1 | 2セルをまとめた1区画 | 2スペース申込み用 |
| 長さ3・3サークル用長机 | 3×1 | 1セルずつの3区画 | 正面・向きは型に持たせる案 |
| 長さ3・2サークル用長机 | 3×1 | 両端の1セルずつ、2区画 | 中央は席ではないが机の占有範囲 |
| フリースペース | 2×2 | 全体で1区画 | 机はなく、4方向が入口 |
| ブース | 3×3 | 全体で1区画 | 1～3辺が壁、残りが入口 |

型そのものと、配置時の位置・回転は分けます。例えば長机の4方向を別々の型として登録する必要はありません。型の区画・辺の情報も配置時の回転に追従させます。

## 提案するデータの分離

以下は設計案であり、クラス名・保存形式・操作方法は未確定です。

### 配置物の型

- ID、名前、種類（机・場所・ブースなど）。
- 相対セルで表す占有範囲。
- 割当区画の一覧。各区画にIDと相対セル集合を持つ。
- 辺ごとの壁・入口・正面などの情報。

区画はサークルを割り当てる単位です。2セルや9セルでも1区画にできます。占有範囲には属するが区画には属さないセルを認めます。区画同士の重複と占有範囲からのはみ出しは検証が必要です。

### 申込スペースの定義

- 安定したID。
- Excel / CSVとの対応に使う文字列（例: `1`、`2`、`長机1/3`）。
- 表示名・説明。
- 割当可能な型・区画の対応。

表の表示は［申込スペース］の1列にまとめます。文字列を単純に数値へ変換したり、`1/3` を面積比として計算したりせず、アプリ共通の定義へ対応付ける案です。内部IDを保持すれば、表示名の変更で割当関係が壊れるのを避けられます。

| 読込み値 | 初期定義の意味 | 割当先の例 |
| --- | --- | --- |
| `1` | 長さ2セルの長机の1席 | 2サークル用長机の1セル区画 |
| `2` | 長さ2セルの長机全体 | 1サークル用長机の2セル区画 |

現在の1台の長机に「1スペースを2件」または「2スペースを1件」を置ける挙動の移行方法は未決定です。型を別にして置換する方式か、同じ型に排他的な区画構成を持たせる方式かを決める必要があります。両方の区画を同時に有効にして重複割当てさせてはいけません。

### 配置された物と割当て

配置物は型ID、位置、回転を持ち、サークルはその配置物の区画へ割り当てる案です。申込区分と割当区画の互換性を検証します。実物の大きさ、セル数、申込みの数量は同一視しません。

番地は全占有セルではなく、配置に使う区画へ付ける案です。中央の席ではないセルに番地を要求せず、ブースには全体で1つの番地を付けられるようにします。現行の机番号・セル番地・Excel出力条件との統合は、実装前に確認します。

## ［スペース定義］モードの提案

［サークルデータ］→［スペース定義］→［机配置］の順で置く案を推奨します。読込み値の意味を確認してから、型を選んで会場に配置する流れを作れます。この順序でモードを追加しました。

モード内を次の2つに分ける案です。

- ［配置物の型］: 型一覧、追加・複製・削除、名前、占有形状、割当区画、壁・入口の編集。
- ［申込スペース］: 読込み値の一覧、名前・説明、割当可能な型・区画の対応付け。

左に定義一覧、右に選択した定義の図と編集項目を置く案です。占有範囲を枠、割当区画を色と境界で示します。申込スペースの対応付けでは、型のプレビュー上で許可する区画を選びます。型の定義は会場の配置案ではなくアプリ全体で共有します。

［机配置］では定義済みの型を選んで置き、［サークル配置］では申込スペースに合う区画へ割り当てます。机以外も扱うため［机配置］というモード名を変更するかは未決定です。

## 実装済みの範囲（2026-09-13）

- ［サークルデータ］と［机配置］の間に［スペース定義］モードを追加。
- 型と申込スペースの2つの一覧・プレビュー、追加・編集・複製・削除。
- 型の編集はWindowsダイアログで行う。幅・高さ（1～12）、セルをクリックして区画1～9・席ではない占有セル・範囲外を指定し、各辺の壁・入口・正面・開放を選べる。
- 申込スペースは読込み値・説明・割当可能な型と区画のチェックリストを編集する。
- 初期値として6種類の型と申込スペース `1` / `2` を用意。
- 保存先は実行ファイルの隣の `space-definitions.json`。イベントJSONに定義を複製しない。同じアプリ配置先から起動するイベント間で共有し、別フォルダーへ更新するときはこのファイルも引き継ぐ。
- 保存時に参照先の消失・読込み値の重複・不正な形状を拒否し、別プロセスによる上書きを検出。壊れた保存ファイルを初期値で上書きしない。
- 保存は［保存］で確定し、［キャンセル］では変更しない。現在、定義変更の全体Undo/Redoは未実装。
- ［机配置］の画面表記を［スペース配置］へ統合。左上の［次に配置］から共通型のカタログを開き、型と方向を選択できる。［スペース追加］で選択中の占有範囲・壁・入口のゴーストを表示し、連続配置できる。カタログの確定は現在の道具を切り替えない。
- 配置時には共通定義IDと、その時点の占有セル・区画・外周辺をイベント内の `DeskType.Space` に保存する。定義内容のハッシュを型IDに含め、定義を編集・削除しても配置済みの形を変えない。型の登録と配置は編集エンジンの1操作とし、Undo/Redo・JSON保存に対応する。旧データの型は `Space` なしでも読み込める。新しい型のデータは旧版アプリでは読み込めない。
- **サークル割当てはまだ従来の必要セル数に基づく。申込スペースと区画単位の割当て、席ではないセルの割当拒否、番地の省略、出力・最適化との接続は次の段階。** カタログの区画色は定義のプレビューであり、この段階で区画制約を保証するものではない。空き領域への自動配置も従来の標準型を使用する。

実装: `Desktop.Core/Persistence/SpaceDefinitionStore.cs`、`Desktop.Windows/VenueEditorGame.SpaceDefinitions.cs`、`Desktop.Windows/SpaceDefinitionDialog.cs`（各パスの先頭に `CircleSpaceCoordinator.`）。

## 未決定事項

- `長机1/3以上` のような振替許可を初期版で扱うか。提案は面積だけの自動比較ではなく、許可する型・区画の明示的な対応付け。
- セルの物理寸法。長さ2と長さ3が異なる実寸の机なのか、同じ実物の分割数なのか。後者なら異なるグリッド尺度を混在させずに表す設計が必要。
- 1サークルで複数区画を申し込む場合の数量・連続性・同じ机に収める制約。
- 合体サークルと排他的な区画構成、空き席、仮置き、交換の扱い。
- 壁・入口を外周の辺単位で持つか、セルの辺単位で持つか。入口の向きを評価へ反映するか。
- 配置済みの型を新しい定義へ明示的に移行する機能。現在は配置時点の形を保持する方式で、黙って割当てを消さない。
- 未登録の読込み値・空欄の扱い。表で解決できるようにし、勝手な型の推定は避ける案。
- 番地が必要になる時点と、机番号・区画番地・出力列の関係。
- 自動最適化の型互換性、島評価、壁・入口と手動接続の整合性。

## 実装を進める順序の案

1. この6例と旧データを使い、占有範囲・区画・申込区分・互換性のモデルを確定する。
2. JSON保存、旧 `1` / `2` の移行、検証、編集操作とUndo/Redoを整える。
3. ［スペース定義］モードで型と申込区分を編集できるようにする。
4. 読込み・サークルデータ表を［申込スペース］へ接続し、未解決値を確認できるようにする。
5. 型選択による配置、回転、区画への割当て、番地入力・出力を接続する。
6. 島定義、合体、仮置き・交換、自動最適化への影響を検証する。

最低限、6種類の配置と回転、席ではない中央セルへの割当拒否、ブース全体での1区画割当て、旧イベントの保存・再読込み、Undo/Redo、型不一致の拒否を確認します。既存の2スペースサークルと番地出力を退行させないことも検証対象です。
