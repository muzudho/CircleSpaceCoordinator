# 知見の編集と作業者・提供者

更新日：2026-09-19

後続の計画と実装状況は [マルチユーザー共同編集計画](マルチユーザー共同編集計画.md) を参照。変更者名・変更日時・１行チェンジログを［変更タグ］としてパッケージ項目ごとに保持する。ジャンルコードの網掛け・ブロック色では変更後の画面終了時にチェンジログを必須にし、他の編集画面への展開は残作業。

## 要望

### ジャンルごとの知見コメント（2026-09-19）

［ジャンルコードと網掛け］の表に［知見コメント］欄を追加。［主色］［副色］は従来の約半分の幅とし、白黒見本欄ではパターン名を表示せず見本を欄いっぱいに描画する。パターン選択画面の名称は選択時の説明として残す。

各ジャンルの補足（例：RPG に「アクションRPGを含む」）を、最大1000 Unicode スカラー値の１行で保存する。表では下線付きテキストの末尾に［］を付け、幅に収まらない部分を省略する。表示の省略では保存文字列を切り詰めない。クリック、または左右キーでコメント欄へ移動して Enter を押すと、既存のテキスト入力ダイアログで全文を編集する。空欄で確定すれば削除、ダイアログのキャンセルでは元のコメントを維持する。

保存フィールドは各 `GenreStyleDefinition` の任意の `knowledgeComment`。コメントだけの修正も対応表の変更として扱い、ページを閉じる際は変更タグのチェンジログが必要。［破棄］ではページ開始時のコメントへ戻る。プロジェクト保存・Undo/Redo・ジャンル対応表のパッケージ受渡しでも保持する。コメントを持たない旧データは空欄として扱う。

部分書出しのたびに説明を書くのではなく、プロジェクトの編集ページで知見を記入して保存する。現在の作業者のHandleはアプリケーション設定に記憶し、画面最上部に表示する。2026-09-19の追記で、80文字の名前から最大16文字のHandleへ変更し、最初の作成者の表示よりも直近の変更者と変更日を優先する。

## 現在の機能の棚卸し

［プロジェクト → 部分書出し → 知見・ライブラリー］には、次の２つの入口がある。

| 入口 | 現在できること |
| --- | --- |
| 知見の保存・列対応 | 評価チャンネルを選び、説明・入力ルール・係数・重み・会場情報を独立した知見として保存。保存した知見を閲覧し、実際のサークル表の列に明示的に対応付けて、新しいチャンネルを追加する |
| ファイルライブラリー | パッケージをフォルダーから探す。名前・ファイル全体のメモ・タグで検索し、プレビュー、部分読込み、ファイル全体のメモ編集、共通カタログ登録の取消しを行う |

知見に保存する項目は次のとおり。

| 項目 | 意味・編集方法 |
| --- | --- |
| 名前 | 元チャンネルの名前 |
| 説明 | その知見についての説明 |
| 狙い・適用条件 | 何を実現するか、どんな場合に使うか |
| 推奨列名 | 利用先の表に用意する列の目安。自動的には対応付けない |
| 列の意味 | 入力列が表すもの |
| 数値の意味 | 例：1=書籍あり、0=なし |
| 許可値 | カンマ区切りの数値。未指定なら有限の数値を許可 |
| 空欄の扱い | 0として扱うか、エラーとするか |
| マル秘 | プロジェクト・元チャンネルがマル秘なら解除できない |
| 係数・既定重み・座標別の重み | 元チャンネルから保存。知見入力画面では数値を編集しない |
| 会場 | 寸法・障害物・ゾーン。重みの列対応時に形状を検証する |
| チャンネル・重みのコメント | 元チャンネルのコメントを引き継ぐ |

知見はプロジェクト内に保存される。未対応付けの知見は配置評価に影響しない。パッケージ書出しで知見を選択でき、「ひな形のみ」なら会場と座標別重みを除外できる。サークル実データは同梱しない。

調査時点では、同じIDまたは名前の知見を再保存すると重複エラーになり、保存済み知見の上書き専用画面はない。

## 各編集ページからの記入

| ページ・対象 | 記入する内容・入口の案 |
| --- | --- |
| フレーム配置・重みチャンネル | 選択チャンネルの知見を直接開き、説明・狙い・列ルールを保存・上書きする |
| サークルデータ | 列の意味・許可値・空欄の扱いを記入する入口を設ける。対応するチャンネルを明示する |
| 島定義 | 島や接続の設計意図は所属する配置案の説明として記入。独立した島の知見モデルは現在ない |
| ジャンル配置・サークル配置 | 使用中のチャンネルの知見を閲覧・編集できる入口を設ける |
| フレーム配置案 | 既存の［配置案の説明］を利用。知見の説明とファイル全体のメモを混同しない |
| フレーム定義・申込定義・会場 | 部品の説明を編集ページで保存して書出しに引き継ぐ。申込定義には既存の説明欄がある。その他の独立した知見欄は追加設計が必要 |
| 配置決定・書出し | 保存済みの内容を確認して選択。パッケージ全体のタイトル・メモ・タグは書出し側で記入する |

すべてのページに同じ入力項目を置くのではなく、編集対象と保存先が分かる入口にする。知見ライブラリーの管理画面は共通入口として残す。

## 人物情報の記録ルール

- 内部名は `Handle`、設定ファイル `application-settings.json` のキーは `handle`。旧 `workerName` を読んで移行する。プロジェクトを切り替えても維持し、他人のパッケージを読んでも変更しない。
- 画面最上部に［作業者］と現在の名前、名前を変更する入口を置く。未設定は未設定と表示し、OSのユーザー名を勝手に採用しない。
- 知見の記入時・上書き時には直近の変更者と変更年月日を記録する。同じ人でも別の日に変更したら日付を更新する。新規データの最初の作成者は別途記録しない。既存の `author` は読込み互換性のため保持する。
- Handleは前後の空白を除去し、Unicodeスカラー値（コードポイント）で16文字以内とする。UTF-8なら最大64バイト。UTF-16のサロゲートペアは1文字と数える。結合文字や複数コードポイントの絵文字は、見た目が1文字でもそのコードポイント数を数える。壊れたサロゲート・改行・制御文字は拒否する。
- 旧設定に16文字を超える名前があっても黙って切り捨てず、設定値を保持する。知見記入・書出し前に有効なHandleへ変更する。
- 提供者は記入者・変更者とは別の情報。パッケージの部品ごとに最初と直近の２名を保持する。受取りだけでは提供者を更新せず、再提供時に直近を更新する。
- 対象部品は、フレーム配置案、部分配置、チャンネルの知見、会場、フレーム定義、申込定義。申込定義や配置案に同梱される参照先定義にも情報を持たせる。
- 改名やIDの割当て、プロジェクト保存・再読込み、共通カタログ登録、パッケージ再書出しで情報を失わない。
- A→B→Cと再提供した場合、最初=A、直近=Cとする。途中の全履歴は今回の対象外。
- 旧データの人物情報は不明として扱い、過去の作者を推測しない。旧知見の上書きでは変更者だけ記録する。提供者情報のない部品は、今回初めて記録できた提供者を最初として扱う。
- GUIでは、知見・コメントの記入とパッケージ書出しの前に、未設定なら作業者名の入力を求める。キャンセルすれば操作しない。既存のCLI・API利用との互換性のため、名前を指定しない旧リクエストも受け付ける。

## ジャンル配置の表示と変更履歴

配置図のサークルにマウスを重ねたときのジャンル表示、および右側の配置案一覧の説明の左端に、`by muzudho since 2026-09-19 ｜ 文芸` のように表示する。対象はそのサークル配置案を最後に変更した作業者であり、パッケージを最後に書き出した人ではない。配置案一覧ではマウスを重ねた案の情報を使用する。

変更日は画面最上部の右端に表示する作業日を `YYYY-MM-DD` で保存する。作業日はアプリを実行している環境のローカル日付で、編集操作へ明示的に渡す。エンジンが別の日付を決め直さない。配置操作・改名・空席への自動配置・最適化で変更者を記録し、通常保存、Undo/Redo、再読込みで保持する。長時間の自動処理は開始時に渡した作業日を使用する。取込み・再書出しだけでは内容の変更日を更新しない。古いデータに変更者や日付がなければ「変更者不明」「日付不明」と表示し、現在の作業者や今日の日付を推測で入れない。

アプリに完全な変更履歴や人物別の一覧は実装しない。**詳細な変更履歴が必要な場合は、プロジェクトJSONなどをGitで管理してください。** アプリ内のUndo/Redoは通常の編集操作用として残す。

## 実装・検証の確認項目

- 設定ファイルへの保存と再起動後の復元、16文字境界、日本語・補助平面の絵文字・結合文字・不正サロゲート。
- 知見の新規保存、本人による上書き、別人による上書き、Undo/Redo、旧知見の取込み。
- Aが提供→Bが読込み・改名→通常保存・再読込み→Bが再提供→Cが取込み、という往復。
- 配置案、部分配置、知見、会場、定義、参照先定義、共通カタログそれぞれで最初の提供者を保持。
- 手動JSON変換を行う保存処理とJSONスキーマにも人物情報を追加し、読込み時に人名の上限を検証する。

## 今回実装した範囲

- プロジェクト一覧と通常の編集ページの最上部に作業者を表示。作業者欄をクリックして変更し、アプリケーション設定へ保存する。
- 各編集ページの最上部に共通の［知見ライブラリー］入口を追加。部分書出しを開かずに、チャンネルの知見保存・列対応・保存済み知見の編集ができる。
- 保存済み知見は［選択した知見を編集］から編集する。元チャンネルを再保存するときは同名の知見を［知見を上書き］で更新する。後者は現在のチャンネルの係数・重み・会場を採用する。
- チャンネルの知見保存で説明・狙い・入力ルールを元チャンネルにも記憶する。保存済みの独立した知見だけを編集する場合は、使用中チャンネルを自動変更しない。
- 知見とチャンネル・重みのコメントに直近の変更者・変更日を記録。知見の詳細表示も `by Handle since YYYY-MM-DD` 形式とする。
- パッケージ書出し時に部品と同梱定義、配置内の各フレームへ最初・直近の提供者を付与。読込み・改名・共通カタログ登録・通常保存で保持する。部分配置を別の案へ挿入しても各フレームの人物情報を保持する。
- 書出しファイルの保存に成功した後、書出し元プロジェクトにも提供者情報を記憶する。書出しダイアログの取消しだけでは変更しない。記録操作はプロジェクトのUndo対象であり、既に保存した外部パッケージの内容はUndoでは変わらない。
- JSONの `credits` に `modifier` と `modifiedOn` を保存。従来の受渡し情報 `firstProvider`・`latestProvider` は表示用の変更者とは別に保持。旧 `author` も読込み可能。通常プロジェクトとパッケージ、JSONスキーマを対応させた。

ページごとに異なる専用知見フォームや、会場・フレーム定義用の新しい説明欄は今回追加していない。上表のページ別案として残し、共通入口から既存のチャンネル知見を記入できるようにした。アプリ本体の全画面で最上行を作業者・作業日専用とし、定義・配色編集画面とアプリ内ダイアログでも常時表示する。定義・配色編集のレイアウトは、この行を避けて配置する。

## ジャンルコードの色・網掛け編集

- 画面を閉じる操作は［閉じる］に統一。［保存］［キャンセル］の２つを置かない。
- 編集中は、［閉じる］の左に次のように表示する。
  - 未変更：`by 一郎 since 2026-09-18 ［閉じる］`
  - 変更あり：`(by 一郎 since 2026-09-18)  (by 二郎 since 2026-09-19) ［閉じる］`
- 前回の情報は、この対応表全体の最終変更者と変更日。今回の情報は最上行の作業者と作業日。初回で前回情報がない場合は不明と表示する。
- 主色・副色・網掛けのどれかが編集開始時と異なる場合、［閉じる］で対応表を反映し、今回の作業者と作業日で最終変更情報を更新して自動保存する。
- 変更せず閉じた場合、または配色を元に戻した場合、対応表も人物情報も更新しない。単に画面を開いたことで既定の配色を保存したり、更新日を変えたりしない。
- 画面のEsc・Ctrl+Sも変更を反映して閉じる。色・網掛けの選択パネルのキャンセルは、選択前の表へ戻る操作として残す。
- アプリ終了時にも開いている対応表の変更を反映して保存する。反映・ファイル保存に失敗した場合は閉じずに内容を保持し、再試行できるようにする。
- JSONでは、ジャンルの対応表全体に `genreStyleCredits`、ブロック番号の対応表全体に `blockStyleCredits` を保存する。どちらも `modifier`・`modifiedOn` を持ち、Undo/Redoと通常保存・再読込みで保持する。以前の全履歴は蓄積しない。
- 同じ編集画面を使うブロック番号の色・網掛けにも、同じ閉じる操作と前回・今回表示を適用する。
